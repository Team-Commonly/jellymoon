# P06R: the shared toolchain cache lands from PR #8

**Changed.** PR #8's two tools commits, cherry-picked onto main without its design base (which landed separately as
NS): `scripts/tools.sh` reads `JM_TOOLCHAIN_CACHE`. Set, Go and Bun live once in the cache and a worktree's `.tools/` is
three symlinks; a cached toolchain is used without taking the lock, and a killed installer's leftovers are recovered.
Unset, nothing changes. Archives are deleted after a verified unpack in both modes. Round 2 (owner ruling): the cache
root, each entry used, Go's `bin/` and the linked binaries must be the current user's own, not symlinks, and not group-
or other-writable, or `tools.sh` refuses before it runs anything in them. `scripts/check-tools-cache.sh` proves it
inside `make preflight`. The doc now says what the check refuses and what it cannot stop. Unset mode makes its version
dirs 0755 again, and Bun's checksum line is matched exactly. See `docs/development/toolchain-cache.md`.

**Evidence.** 12 fixture cases, with nothing downloaded; 11 of them fail against round 1's `tools.sh`, and five mutants
of the check are each caught. Under a clean shell, `./init.sh` and `make preflight` are green with the cache unset, and
`make preflight` is green again with it set to a fresh directory, which installed and was then reused.

**Next.** Pin the Go and Bun checksums in the repo, so a cached entry can be re-verified on use; an atomic dead-lock
takeover and the `kill -0` EPERM case; a one-time cleanup of older worktrees' downloaded archives; a `docs/INDEX.md`
row for the cache doc.

**Surprising.** An installed `.tools/` was 356 MB, not the 460 MB estimated, plus 104 MB of downloaded archives that
were never deleted. Both of round 1's cache checks read the entry they were judging, so a planted entry vouched for
itself; only who can write to the cache decides whether it can be trusted.
