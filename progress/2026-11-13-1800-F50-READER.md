# F50: the reader leaves out a run's copy

On branch `f50-reader`, one commit on top of `ea8fc69` (`adr-18`). `feature_list.json`: F50 `passes` is `true`,
nothing else changed. The rule and what it does not close: `docs/development/reader.md`, "A run's copy is never
read". Why: ADR 0018, decisions 6 and 7.

## What was built

- `crates/jellymoon-core/src/session/copies.rs`: `Copies`, the home's `copies` folder under two spellings (the
  home as given, and as the system resolves it when it is there), and `hold`, which says whether a log's folder
  is below one. The log's text is compared as text, name by name, with no list of its names made.
- `session.rs`: a read takes `Left` (the names switched off, and the copies) where it took the names. A line
  whose folder a copy holds starts no turn and is no reply; a typed one still ends the turn before it.
- `reader.rs`: `typed_on` builds `Left` from the options. Every read goes through it, so nothing else changed.
- No type or printed JSON changed, so no example file did. No new dependency.

## Every caller of the reader

All four go through `reader::typed_on`.

| Caller | Reached from | Proved by |
|---|---|---|
| `reader::day` | `jellymoon day`, `jellymoon page` | `tests/f50.rs`, seven tests; the call's input is compared byte for byte |
| `reader::folders` | `jellymoon run` and `run show` with no `--repo` (`run/place.rs`) | `tests/f50.rs`, the last test, both commands |
| `reader::day` | the app's day (`app/src/today.rs`) | `app/tests/f42.rs`, one test of `layout --fresh` |
| `reader::typed_in` | `wishable` and `wish_offered`, which only the app calls (`app/src/wishing.rs`) | core's test in `reader.rs`; the app's chips above come from it |

`jellymoon wish` does not read the day. `wish --run` reaches `run/place.rs`, the second row.

## Tests, and whether each was red first

All eight of `crates/jellymoon/tests/f50.rs` were red against `ea8fc69` before core was touched. Core's tests
were written with the rule. The app's test was red under the mutation that never tells the reader the copies.

## Mutations

Thirty, one at a time, each against core's tests of the rule and against F50's at the binary
(`cargo test -p jellymoon --test f50`). Every one was killed by one of the two; none survived both.

| Mutation | Core | Binary |
|---|---|---|
| the resolved spelling dropped; the spelling as given dropped; both spellings must match | killed | killed |
| compared by string prefix; a name matched by its start; by its end | killed | killed |
| `copies` itself taken for a copy; only deeper than a copy; only the copy and nothing deeper | killed | killed |
| the answer inverted; the home itself taken for `copies`; the reader never told the copies | killed | killed |
| a `..` below allowed; `.` a name; an empty name a name | killed | killed |
| any case on every system; `\` parting names on every system | killed | killed |
| a typed line in a copy is a turn | killed | killed |
| a reply in a copy is a reply; a typed line in a copy does not end the turn before it | survives | killed |
| exact case on Windows; `\` parting names nowhere; the long spelling not read; a long shared folder taken for a drive | killed | survives |
| the root not compared; `//x` not `/x`; a path that is not full taken; any first name a drive; a path from one `\` full on Windows; a home with `..` naming copies | killed | survives |

First pass: "a name matched by its end" survived both, and so did two that made a Windows home with no drive
a full path. Each got a case (`old-copies`, a home's spelling that is not full) and was killed on the second
pass. Two more survived the binary and got a case there: `.` as a name, and `\` parting names on a Mac. One
mutation turned out to be no change at all, and the code it guarded was taken out: the long spelling was
stripped only on Windows, and off Windows what is left of one is never a full path.

Survivors, with the reason:

- **Two in core**: how a copy's line sits among a session's other lines is `session.rs`'s loop, which the
  binary's test of a mixed session holds and no unit test does.
- **Four at the binary** are Windows' spellings: the binary's tests write the paths of the system they run on.
  On Windows the test of the resolved home writes a `\\?\` path, and the case and `\` cases flip by `cfg!`.
- **Six at the binary.** Four change only what a path that is not full, or a home that is not full or climbs,
  is taken for: a command refuses a home that is not a full path before the reader runs, and a log's folder
  that is not full can match no spelling that is. Two are about the root, which off Windows differs only for a
  path that starts with two separators, and no test at the binary writes one. Core's tests hold each on the text.

## Not run, not closed

- Nothing was run on Windows or Linux. Windows' spellings (`\`, any ASCII case, `\\?\`) are held by core's
  tests of the text, which run on every system. The binary's tests take the two Windows-only cases by `cfg!`.
- The test with a link in the home's path is Unix only: making a link to a folder on Windows needs a right a
  test cannot count on.
- What the rule does not close is listed in `reader.md`, "Not closed". The one a later feature may meet: a home
  that was moved or removed leaves its old copies' sessions to be read.
- On this Mac `realpath` gives a path in the case the disk keeps (asked once, by hand, on APFS). A
  case-sensitive volume was not tried.
