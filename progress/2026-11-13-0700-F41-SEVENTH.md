# PR 148's second gate: a detached `HEAD` holds nothing, and a rebase or a bisect stands on a branch

On branch `f41-fifth`, on top of `1e5a7f6`, with `origin/main` (`f99fb81`) merged in. Gated: it changes which
branch a look removes. Docs: `docs/development/run.md` ("What is kept", "What is not closed") and `copy.md`.
Tests: `crates/jellymoon/tests/f41/stood.rs` (new) and `shapes.rs`.

## What changed, by the coordinator's ruling

1. **No `HEAD` in the question of the refs.** `back::theirs` asks `rev-list <branch> --not --exclude=<branch>
   --glob=refs/*` and nothing more. The `rev-parse HEAD^{commit}` step is gone.
2. **The commit the copy was made at.** `Record.base` (left out of the file when none) is the hash `make`
   already asked of git before the worktree is made. A branch whose tip is that commit goes, asked after the
   stood-on rules and the symbolic refs, never before them. A record with no `base` falls to the `rev-list`.
   - *The hash is not checked as 40 or 64 hex by a step of its own.* It is compared whole with what
     `rev-parse --verify` printed for the branch, which is a full hash, so nothing else is equal to it. A
     separate check would be a line no test could fail.
   - *What a lying record loses.* A branch whose tip is exactly the commit the lie names, with the person's
     commit on it, when nothing stands on it and no ref names it. The commit stays in the repo with no ref
     until git's `gc`. Bounds: only `jellymoon/run-<id>`, only in the repo that passes `asked` (it lists the
     copy), only by someone who can write the home and knows the tip. Before this field a record could not do
     that. It is in `run.md`'s not-closed list.
3. **A rebase or a bisect stands on a branch.** `back::stands` asks `symbolic-ref HEAD` and reads
   `rebase-merge/head-name`, `rebase-apply/head-name` and `BISECT_START` in the repo's git folder and in each
   other worktree's (`back::state`): each name on the way a real folder, the last a plain file of at most 8192
   bytes, by `symlink_metadata`. Anything else there is a checkout that could not be asked: the take-back is
   put off, which keeps the branch. The name is matched whole (`refs/heads/…`, as a rebase writes it) or short
   (as a bisect writes it).
4. **A record whose `repo` or `own` is not a full path** reads as a repo that could not be asked: nothing in
   the repo, nothing in the home, and the thirty days run. I chose that over "answers and does not list",
   which would remove the home's files on a record nobody can place.
5. `tests/f41/asked.rs`: the cut-off look's first step is `for-each-ref`, since a branch that has not moved
   is no longer asked by `rev-list`.

## Not closed

- New, and in `run.md`: a lying `base` (above); a record of an older build with no `base` keeps the branch of
  a copy made of a detached checkout; a checkout detached by hand at a branch that has not moved loses the
  branch's name and no commit; a bisect started from a detached `HEAD` names no branch; something other than
  a plain file where git keeps a rebase's branch puts the take-back off for thirty days.
- From the gate's findings 4 and 5, now in `run.md`: a locked copy (the branch goes, the registration stays);
  a link left in `copies` at the give-up; a hand-made second repo that lists the copy; a commit reset away.
- Carried: another folder at the repo's path; `git worktree prune` between looks; a command killed inside git;
  an orphan git child; an unreadable record; `copies` removed or a link; Windows drives that do not resolve;
  thirty days tested by editing the record, with a minute's margin; the cut-off test uses a stalled git; the
  line is not said by the app or by `jellymoon run`.
- Windows, read and not run: `state` builds its path with `push` of each part and reads it with
  `symlink_metadata`, the same on every system; `BISECT_START` and `head-name` hold forward slashes and are
  compared as text with the ref's name, which git writes with forward slashes everywhere. The rebase scenes
  need no editor: the one that goes on uses `--apply`, the other is aborted. Windows is only linted.
