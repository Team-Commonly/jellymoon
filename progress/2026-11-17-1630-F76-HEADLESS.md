# F76: what another program sent to a headless Claude Code is not on a person's page as their words

**What changed.** On branch `f76-headless`, on main `4fac595`. Core's reader, the binary's tests and `reader.md`;
no app, no kit, no new dependency. `feature_list.json`: F76's `passes` is `true`.

- **The rule** (ADR 0021, decision 4). A session line whose `entrypoint` is `sdk-cli` is no turn and no reply. It
  is one function, `Line::headless` in `crates/jellymoon-core/src/session.rs`, asked once for each decoded line
  and joined with the yes or no of a run's copy (`out`), so a headless line goes exactly as a copy's line does: a
  typed-looking one still ends the turn before it, one the agent said is no reply and ends nothing, and its `uuid`
  is not held. The value is compared whole and exactly; no `entrypoint`, another string and a value that is no
  string are read as before.
- **Where a session line's fields are read.** One place: `session.rs` (`decode`, then `prompt`, `reply` and
  `Line::headless` inside `read`). `session::turns` has one caller, `reader::typed_on`, which `day`, `page`, a
  run's search for its folder and the projects on offer all go through. `session/copies.rs` compares a folder's
  text only. `hear.rs` and `run/stream.rs` borrow `next_line` for streams that are no session log. The app reads
  no log. There is no second copy of the rule.
- **Four notes from the gate of PR 188.** The doc comment "The day, and every turn typed on it" is back on
  `typed_on`. A link that leads nowhere at `--logs` is refused in the fixed words of a file; nothing at all under
  the name is still "no logs". `reader.md` says `run` refuses such logs only with no `--repo`, and that a kept
  page that says no logs were found is not shown under the app's note. `tests/f63.rs` tries `run` too, and the link.

The final round on a Mac, in one hold of the lock: `cargo fmt --all --check`, `cargo xtask check`, clippy on core,
the binary and xtask with warnings denied, core's tests, all of the binary's tests, `cargo xtask smoke`.

**What's next.** Nothing here ran on Linux or Windows. The dangling link has a test on Unix only; Windows has the
rule and no case of it. The app's tests were not run: no app code changed.

**Surprising.**
- A headless line's `uuid` matters in both directions: read first it must not hide the person's line, and read
  after the person's line it is dropped as any copy is. The second needed no code.
- A line with no folder is judged, for the copy rule, by the line before it. That memory is kept apart from the
  headless yes or no on purpose (mutation 15): a headless line is in no copy.
- Not proved by a sample: a file with both kinds. The fixture is typed from the rule, as the ADR says.
- Known and not guessed at: a person's own `claude -p` is left out too, and nothing says so.

**Deleted.** Only the sentence in `reader.md` that a prompt another program sent has no `origin`, and the doc
comment's wrong place. Budgets: core 14943 to 14995, the binary 25083 to 25388.
