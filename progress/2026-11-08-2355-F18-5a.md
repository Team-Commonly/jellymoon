# F18 PR 5a: the Playwright harness and the approve-keyboard and needs-you specs

**Changed.** `web-e2e/` holds the browser specs and their harness (docs/development/browser-specs.md). `approve-keyboard.spec.ts`
and `needs-you.spec.ts` each run at 390x844 and 1440x900 in Chromium. The global setup starts the pod-state server (ENV=local,
fresh PGlite dir, free port, `JM_WEB_DIR=web/dist`). The fixture seeds a fresh pod per test through the real routes: an owner, a
member by invite, and the fake agent, a computer plus agent that gets its run token the daemon's way and posts asks with it.
`make e2e-web` builds the client and runs them; CI's `browser` job (10 min timeout) installs Chromium inside the job and
uploads the report and traces on failure. The server serves the built client when `JM_WEB_DIR` is set (`server/src/web.ts`).
New dev dependencies: @playwright/test 1.64.1, ws 8.21.0 (ADR 0001 rows).

**Evidence.** Locally: `playwright test --list` enumerates 4 tests (2 specs x 2 projects); tsc over web-e2e; vitest web 75
passed; server tests 45 passed (3 new, 2 mutants caught); `make entropy private portable check-gen` green. The specs themselves
have not run anywhere yet: browsers are installed in CI only, so the first run is the PR's `browser` job.

**Why the bridge.** On main the pod socket reads its token only from `Authorization` on the upgrade, which a browser cannot set.
The fixture routes the page's socket (`page.routeWebSocket`) to a Node-side socket with the token and relays frames unchanged.
It also holds the server's frames on demand, which is how approve-keyboard shows the card still waiting while the pod has ruled.
With the browser session on the socket, the fixture can sign in by cookie instead.

**Not here.** device.spec and invite.spec (need the browser sign-in), layout.spec (PR 5b). `feature_list.json` untouched: F18 is
not passing.

**Surprising.** A plain GET of `/v1/pods/:pod/ws` (no upgrade header) is a 500 on main, not a 404: the upgrade middleware falls
through to the upgrade handler. Left as it is; noted for a server unit.
