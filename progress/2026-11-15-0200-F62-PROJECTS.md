# F62: the projects Jellymoon knows, at `jellymoon project`

**What changed.** On branch `f62-projects`, on main `e1ba272`, with the gate's fixes in a commit after it. Core's `project.rs` keeps the list
(`projects.json` in Jellymoon's folder) and `project/offer.rs` is the one lookup from a project's name to its folder:
`wishable`, a run with no `--repo`, and `run show`, `keep` and `toss` all ask it. `jellymoon project add`, `list` and
`forget` are the list as commands, and a run's start writes its repo there once its copy is made and its lock is
taken. The account is `docs/development/project.md`; what was decided is ADR 0020, "Found while building F62". F62
is `passes: true`.

**The evidence.** `cargo test -p jellymoon --test f62` (31 tests; 25 one-line mutations of the rules, each seen
to fail one), the smoke chain's `project` step, and the examples `project.json`, `projects.json` and
`projects-kept.json`, which round-trip. Two earlier tests changed their answer. `tests/f47.rs` forgets the project
a run listed before it asks for a repo that is not found. `tests/f48.rs` held that a repo's path is in one file of
the home, the run's record: it is now in two, the record and the list (ADR 0020, "Risks left open", 1).

**What's next.** F63 (the page on a day nothing was typed) and F64 to F66 stand on this. The app holds one line that
is now too narrow: its refusal of a wish for a project not on offer still says "typed in". `Error::Project` has its
arm in `app/src/today.rs`; the app was built by the smoke chain only, and its tests were not run.

**Surprising.**
- A repo's top is checked by looking for `.git`, when a project is listed and when it is offered: asking git needs
  the empty folder a run keeps for it, and a look writes nothing. The run's copy still asks git. This is where the
  build is not ADR 0020's words, and the ADR now says so.
- A run named a folder with `--repo` leaves a line for another folder of that name alone, and goes.
- The list is all or nothing: one line `project add` could not have written and none of it is used.
- `cargo xtask check` counts only files git knows, so a new file is counted once it is staged.
- Not run: Windows and Linux, `make preflight`, and the tests of the app and the kit.
- A wish said aloud picks the only project offered, and every listed project that stands is offered every day:
  the smoke chain's `hear` step forgets what the chain's runs listed before it hears.

**Open after the gate.**
- The home is 0700 only when Jellymoon makes it: a home that was there, open to others, holds the list as it is.
  The file is 0600.
- The list's lock is the tap's: one that is 30 seconds old is taken over, and two commands that both find it
  stale can both take it. Not closed here.
- A stray argument to `project` was said back by the usage error, a folder or a credential with it. It is now
  one fixed line; `tests/f62.rs` holds it.
- Two flakes the reviewer saw, neither F62's: xtask's `a_home_is_named_for_its_process_and_its_start...` on two
  equal clock readings, and F40's `late::a_look_that_finds_the_copy_gone...` on a slow Linux runner.
