# F29 · a ruling reaches a running Claude Code session once (2026-11-11)

**What changed.** `jellymoon rule` keeps a ruling as a file in Jellymoon's home; `jellymoon hook` hands each waiting
ruling to the session that runs it, as `additionalContext` on `PostToolUse`; `jellymoon hook install` and `uninstall`
put one piece of text into the harness settings and take exactly it out again. All of it is in core
(`ruling.rs`, `hook.rs`); `docs/development/delivery.md` has the contract used and why.

**Evidence.** `cargo test -p jellymoon --test f29`: 10 passed, 1 ignored. Core: 30 unit tests, 4 shape tests.

**What's next.** F29 stays `passes: false` until a person runs the harness-real step (the command is in
`delivery.md`). The app can call `jellymoon_core::rule` from a tapped clash option.

**Surprising.** Exactly-once needs no lock: a create-new mark file per ruling and session is enough. Claude Code's
exec form (`args`) runs a hook with no shell, which is what makes one entry work on Windows.
