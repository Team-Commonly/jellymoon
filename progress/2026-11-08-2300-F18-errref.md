# F18 errref: the store matches a refused ruling to its own card

**Changed.** `web/src/store.ts`: an error frame with a `ref` lands on the pending ruling whose decision id equals it; with no
`ref` (an older server) the most recent pending ruling takes it, as before; a `ref` naming nothing pending changes nothing. A frame
that is not JSON, or has no string `type`, is dropped and counted in `droppedFrames`, never thrown. When the socket drops, every
pending ruling is re-marked unsent ("may not have reached the pod, choose again") so the card can be ruled again; if the ruling
had landed, the resubscribe replays `message.updated` and the card shows it ruled.

**Evidence.** Four tests committed with the change, run red first (4 failed, 75 passed), then green (79). The mutant that matches
the most recent pending ruling and ignores `ref` fails 2 tests.

**Missing.** The server and Worker socket paths build the error frame from `code` and `message` only, which drops the `ref` the
core already sets on `already_ruled` and `not_found` (F12, open PR 13). Until they pass `ref` through, the store uses its fallback.
`message.post` errors stay ref-less and keep using `postError`.

**Surprising.** The web LOC budget was 14 lines tight, so the tests are compact and the store change is a few dense lines.
