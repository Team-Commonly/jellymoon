# LPRE2: land asks CI to prove the exact merge commit

**Changed.** The first LPRE pass read CI on GitHub's merge ref and found it never carries check runs (runs attach to the PR head), so the skip
could not fire. Now `scripts/land.mjs` builds the merge commit itself (`git commit-tree <merge-result tree> -p <main tip> -p <head>`), pushes it to
`refs/heads/land/<n>`, and waits (20 s polls, 15 min cap) for every required check on that commit from the Actions app. Green skips the local
preflight; red, cancelled, skipped, the cap, an unreadable list or a failed push runs the preflight as before; a land commit whose tree is not the
merge result refuses. The ref is deleted on every exit, and land only ever pushes or deletes a ref built by `landRef` (`refs/heads/land/<digits>`).
`.github/workflows/ci.yml` now also runs on pushes to `land/**`.

**Deviation to know about.** The `dco` job ran only on `pull_request`, and `dco` is a required check, so on a `land/**` push it would be skipped and the
proof could never go green. The job's `if` now also admits a `land/**` push, and on such a push it checks the range between the commit's two parents.
This is a job change, outside the brief's "trigger only"; without it the skip cannot fire. `e2e-preview` also runs on a `land/**` push (it is not
required).

**Changed rule.** A same-named run from another app is now ignored (it neither proves nor vetoes); only Actions runs count.

**Follow-up.** Count `CI proved merge tree` against `local preflight (` in the ledger after a day of lands. The first live land is the first time the
push, the `land/**` trigger and the `dco` change run for real; none of it was exercised against GitHub here (no pushes allowed).
