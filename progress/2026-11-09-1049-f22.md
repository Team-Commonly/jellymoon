# F22 progress (2026-11-09-1049 UTC)

**Changed.** `jellymoon connector connect|grant|approvers|list|receipts`, over the routes ADR 0009 describes and no server or schema change. The upstream credential comes from `JELLYMOON_CONNECTOR_TOKEN` (dropped from the environment once read) or a hidden prompt, through a shared `readSecret` that `import commonly` now uses too. `--access write` is refused before any request; `approvers` needs `--users` and `--users ""` clears the set; a server refusal prints as `<code>: <message>` with exit 1. New: `briefs/F22-conncli.md`, `daemon/internal/api/connectors.go`, `daemon/internal/cli/{connector,connector_read,secret}.go`, `e2e/f22_test.go`. `TestF22` is on the Worker skip list with its reason in `docs/development/e2e-contract.md`.

**Evidence.** `TestF22` first ran 0/5 (the CLI answered with its usage), then 5/5. A mutant that printed the credential after a connect turned the last step red. `make e2e-c` and the daemon `go test -race` are green; see the PR for the counts.

**Next.** A route that lists stored grants and approvers would let `connector list` show who holds a grant; the row asked for "by grant" and the existing list route gives a person the pin only, so the list shows what each access level allows. The hidden prompt is untested under a pseudo-terminal.

**Surprising.** The recording proxy shows the credential in the body of every connect that reaches the server, including the refused ones (a member's, a drifted upstream's). That is the design: the pod holds it. The test therefore counts the three connects instead of asserting one.

**Known limits.** The CLI scrubs the exact credential from the error it prints, but not its encoded forms; the server already does that for what it returns.
