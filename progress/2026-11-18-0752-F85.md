# F85: what a run says of its work is kept, checked at every look, and printed beside the work

**What changed.** On branch `f85`, on `3d38919` (the design, ADR 0023). One commit; in `feature_list.json` only
F85's `passes`. Core and the binary only: nothing in `app/` or the kit (F86), and the schema and the words a run
is asked with are untouched (F87).

- **A last word may be `done` with a `result` beside it** (`run/asks.rs`). The `result` is of any shape and never
  fails a run. Beside `asks`, a question or any other part it is a failed run as before. Named twice it is no
  result and the word is `done`.
- **A result that is the shape and within its size is kept** as `runs/<id>/result.json` (`run/told.rs`, `keep`):
  core's own one-line writing of it, its first twelve pieces, at most 8,192 bytes with its line break. Only of a
  run that finished. Nothing is checked then.
- **A look checks it against the work, every time** (`told::checked`, from `run/show.rs`): `run show` without
  `--file`, and `run waiting`, of work that waits, print `result` (`{pieces, dropped}`) beside what they printed
  before. A text passes the door a question passes and is dropped, never cut. A `change` is printed under the
  file's number and core's own name, only when the file is a text file of the work and every quoted line is a
  whole line the work took from it or put in it. A piece that fails is dropped whole and `dropped` counts it.
- **One new question of git** (`copy/work.rs`, `before`): `cat-file blob <id>` with the id `diff-tree` printed for
  a changed file's old side, for the first two files the result's changes name, read to 64 KiB and one byte,
  through `copy/git.rs` like every other. A path or a line of a result is compared, never given to git.
- **Docs**: `show.md` ("What the run says of its work", the new row of "What is asked of git", `result` in
  `run waiting`, two lines of "What it does not do"), `run.md` (the last word, what is kept, the file that is not
  a plain file), the row of `show.md` in `INDEX.md`.

**The evidence.** Red first at the binary, on `3d38919` with the tests and the made-up agent's script only: 14
of 15 tests of `tests/f85.rs` failed (a run that ended with a result had failed with "its last word was not
`done` alone, or `asks` with one question", and nothing printed a `result`). One was never red: a `result`
beside `asks` or another part fails the run, which it did before. Green now: `cargo test -p jellymoon --test f85`,
17 tests; core's 170 and all 774 of the binary's; fmt, `xtask check`, clippy on core, the binary and xtask;
the smoke chain's 34 steps.

The two that survive are one rule held twice: a file that is not `text` in the list is refused by its kind, and
a side with a zero byte or bytes that are no characters is refused when it is read as text. A file of at most
64 KiB is `text` exactly when the second holds, so either alone changes nothing; both taken out together are
killed. The first three survivors of the first round (the file not of the work, the name, the run that did not
finish) each got a test.

**Decided, where ADR 0023 left room.**

- The size is that of core's own writing of the result, not of the bytes the harness sent: the stream's last word
  is read as a value, and its bytes are not kept.
- Pieces past a kind's count (a second `did`, a third `change`, a fourth `decided` or `unsure`) and past the
  twelfth are left out and are not counted as dropped: they failed no check.
- A result of which every piece failed prints `{"pieces":[],"dropped":N}`; one with no piece at all prints none.
- `result` is printed only of work that waits, and never beside `--file <n>`.
- A file with a side over 64 KiB is not quoted from, and the name of a quoted file must be one read as git keeps
  it (`obeyed.rs`, `plain`).
- The failed run's sentence "its last word was not `done` alone, or `asks` with one question" is unchanged,
  though `done` may now have a `result` beside it: the words are F87's.
- The two note sentences of the ADR ("Nothing was run to try this…", "Something the run said could not be
  checked, so it is not here.") are F86's. Here the count `dropped` is what says a piece was dropped.

**Open.**

- A real harness was not asked for a result: the schema it is given still refuses any part beside `state` and
  `question`, so until F87 only the made-up agent ends a run with one.
- A run that finished and changed nothing keeps its result, and nothing reads it.
- The made-up git catches a word that is a whole argument. A path inside a longer argument would not be caught
  by that test; the code gives git the id alone.
- Linux and Windows were not run here. Two test lines are Unix-only, each under `cfg(unix)`: the kept file's mode
  0600, and a kept file its group can write being no result.
- `did`, `decided` and `unsure` are the run's sentences, cleaned and bounded; nothing compares them with the work.

**Lines.** 1,504 added, 37 removed in 24 files, this one among them. Budgets: core 16285 to 16800, the binary 27335 to 28078 (all
tests). Deleted: nothing but the lines rewritten; the count's pattern moved out of `UNREAD` into `COUNT` in
`obeyed.rs` with the same meaning.
