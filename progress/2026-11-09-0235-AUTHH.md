# AUTHH: sign-in hardening, the open follow-ups of F15 and BSESS

**Changed.** Both adapters (ADR 0008, "Hardening"). A `jmu_` carries `expires_at` (30 days) and is no caller past it, on
every route and the socket. The two unauthenticated starts take 30 requests per client address per fixed minute, then
`rate_limited` with `Retry-After` (server: socket address, `X-Forwarded-For` only with `TRUST_PROXY=1`, in memory; Worker:
`CF-Connecting-IP`, in D1). Device codes and states are swept an hour after expiry. Each GitHub call times out at 10 s. A
GitHub client outside ENV=local needs `PUBLIC_URL` (the server refuses to start; the Worker answers `internal` on the GitHub
routes). A concurrent first sign-in makes one user. Approve takes the user code in either case, with or without the hyphen,
and by cookie needs the server's own Origin. Logout with a Bearer and the cookie revokes both, and closes the sockets opened
with a revoked token. Schema rules first (`make gen`), then the red tests, then the fix.

**Evidence.** Red: STEPS=19/26 (e2e-c) and 18/26 (e2e-a) for TestF15, TestBSESS and the new TestAUTHH; the unit tests did
not load. Green: 26/26 on both, `bun test server worker` 82/82. Four mutants on each adapter, all eight caught: the expiry
check and the rate counter by TestAUTHH, the approve Origin check by TestF15's approve guards, logout revoking only the
Bearer by TestAUTHH's logout step.

**Next.** Existing `jmu_` rows have no expiry and never expire; an existing D1 needs the `expires_at` column and the two new
tables. No token refresh. A socket stays open past its token's expiry. The `/device` page (F18).

**Surprising.** The concurrent first sign-in was red on the Worker at once, but never in e2e on the server with PGlite,
which runs one statement at a time: the server's race is shown by a unit test that starts six sign-ins in one tick, so all
six read "no user" before any writes.
