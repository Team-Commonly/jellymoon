# F92: a finished change is kept by itself, and can be undone (2026-11-24)

ADR 0028. `docs/development/keep.md`, "Kept by itself" and "Undone"; `docs/development/app.md`, "A change kept by
itself".

## Found
Every finished change waited for a tap, also the ones a keep would take with no further question. A person who
asked for a change and got it had one more thing to do before their folder had it.

## Built
- Core, the seam (`run/end.rs`, `run/keep/itself.rs`): once a run's end is noted and before the wish is told, the
  keep of `keep.rs` runs with no yes given. It lands only work that is moved forward or joined, no file the
  person's tools obey, no change to a `.gitattributes`, and nothing `keep --ask` refuses. Whatever refuses it says
  nothing and the work waits as before. The record gains `before` (written with the intent) and `back` (an undo's
  intent); the run's branch stays; `Ran` gains `kept_itself`.
- A change kept by itself on a later day takes the run's branch and `before` of every earlier day's kept change
  of the same repo, under the same lock (`itself::sweep`): the branches kept for an undo are those of one day.
- `jellymoon run undo --wish <id> [--ask]` (`run/undo.rs`, `copy/keep/undo.rs`), under `keep.lock`: the checks,
  then `back` written, then the checks of the branch and the disk once more, then
  `git -c gc.auto=0 read-tree -m -u <kept> <before>` in the folder and
  `git update-ref --no-deref refs/heads/<onto> <before> <kept>`. Neither goes by `HEAD`. Three cut points; the
  next undo goes on from any of them. Only a change kept by itself is undone; one kept by a tap is as it was.
- App (`src/landing.rs`): the note `kept-<wish>`, "Your folder has this change now.", its count and the one
  choice `Undo it`; core's answer after the tap; the work's note of a change that was not kept by itself says
  first that it waits for a yes. `kept-` stands after `work-` in the column's order.
- A test's build reads `JELLYMOON_TEST_WAITS`: 1 makes every change wait. The binary's test support and the smoke
  runner set it, so every test of work that waits is as it was; the F92 tests set 0.

Deleted: nothing but the old first line of the work's note. `stands` and its words moved from `run/waits.rs` to
`run/waits/plain.rs`, unchanged, to keep the file under 400 lines.

## Pins changed, and why
- `app/tests/f47.rs` and `app/tests/result_in_plain_words.rs` (`READY`), `app/tests/f47/drawn.rs` (the line of a
  note with no keep): the first line of work that waits says "It waits for your yes" where it said "It is in a
  copy", since with F92 that is what tells it from a change the folder has already.
- `run/record.rs`'s test of the record's words lists `before` and `back`; `app/src/column.rs`'s test of the
  order lists `kept-`.
- Support only, no assertion: `support/door/world.rs` sets the switch to 1; `app/tests/support/worked.rs` gains
  `landed`; the made-up agent gains the script `attrs`.

## Red first
The code was written before its tests, so the red is the seam switched off: with `keep_itself` answering false,
10 of the 14 tests of `tests/f92.rs` and 3 of the 4 of `app/tests/kept_by_itself.rs` failed; the ones that pass
either way are the ones that pin a change that waits. Six one-rule mutations, each run against `tests/f92.rs`
alone and each killed: a file the tools obey kept by itself; a file in the way not asked; `before` not written
with the intent; an undo under a later change let through; the step written as `reset --keep` (killed by the
test of the step alone: the branch the checkout was switched to moved); the run's branch deleted after the keep.

## Open
- Between the second check and git's own start a file can still appear at a path that comes back. Measured:
  git refuses the step whole for an untracked file there and writes over an ignored one. ADR 0028, "Open".
- A change that was pushed is found only by a name of this repo that holds it (a remote's branch as last
  fetched). A push nobody fetched back is not seen.
- Not run: the smoke chain, a real window, Windows, Linux, the whole suite. Run: the test files listed in the
  commit's report.
