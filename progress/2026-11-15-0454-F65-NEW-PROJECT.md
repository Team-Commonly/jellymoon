# F65: a new project is a folder Jellymoon makes, at `jellymoon project new`

**What changed.** On branch `f65-new`, on main `36d0a9d` (replayed there after F56). `jellymoon project new <name>` makes `projects/<name>` in
Jellymoon's own folder, a repo with one empty first commit, and lists it. Core's `project/new.rs` holds the rule
(the name, what is taken, the order, what a failure takes back) and `copy/fresh.rs` the repo, made by the copy's
own git. The account is `docs/development/project.md`, "A new project"; what was decided, and where it is not the
ADR's words, is ADR 0020, "Found while building F65". F65 is `passes: true`. Two things F62 owed are in: its
fixed-line test tries an argument that is not text and a missing value, and its progress row's last line is right.

**The evidence.** `cargo test -p jellymoon --test f65` (18 tests, seen red first with the command taken out of
the parser: all 18 failed on the fixed `project is` line); 24 one-rule mutations each seen to fail a test; the
smoke chain's `new` step. No new printed shape: `new` prints `project.json`'s.

**What its gate found** (four blockers, fixed in the commit after). A making held between its folder and the
list could be met by another command, and then took back, by name, a listed project with the person's file in
it: the whole making is behind the list's lock now, and only the folder this command made is taken back, known
by the system's number for it and its time of making. Every refusal of the folder after it was made was said
as the file system changing the name: whose Jellymoon's folder is and whether its path is text are asked first,
in their own sentences. Names Windows takes for no folder were made: the rule is wider. The person's config
chose the repo's object format, ref format and who may read it: `init` is told all three. A link to a folder
is removed as a folder on Windows: the tests have one helper. 27 f65 tests; the gate's survivors M5, M10, M15,
M19, M33 and M42 have a test each; 21 mutations, one or more for each fix and survivor, each fail a test.

**What's next.** F66, "Start something new" in the app's entry, stands on this. The PR waits for a gate: it
writes to the person's disk.

**Surprising, and open.**
- The folder is `projects` in Jellymoon's own folder, not `~/Jellymoon`: the Finder does not show it. F66 or
  "Friends" may have to move it, and a move is a change to every listed line.
- F62's check of a name already refuses a space at either end, so that rule is not written twice: two
  mutations of it lived, and it was removed.
- A killed `project new` leaves a folder nothing cleans up, and its lock for half a minute; the next one
  names two ways out and cannot say which.
- The sentence for a file system that stores a name in other letters has no test, and the gate's M17 (the kept
  name is never compared) lives: no disk at hand keeps a folder under other letters.
- A making over 30 seconds long loses its lock, as any change to the list does.
- `Command`'s three project variants are one, `Command::Project(Listing)`: `run()` in `main.rs` was at its
  60 lines.
- The smoke chain's day is full: `project` makes its eighth made wish, so `new` has a day of its own. The
  next step that makes a wish needs one too.
- Run by CI on Linux and Windows, not by hand. The device names and the cut dots are Windows's rules, read
  and not seen.
