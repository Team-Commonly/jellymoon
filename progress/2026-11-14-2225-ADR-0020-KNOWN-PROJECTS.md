# ADR 0020: a project Jellymoon knows (design only, no code)

On branch `adr20-known-projects`, one commit on main. The design is `docs/adr/0020-a-project-jellymoon-knows.md`,
accepted by the coordinator. Nothing was built or run.

## What it answers

ADR 0019's first open risk: a project is offered only when a folder of its name was typed in that day, and the
reader leaves out a run's copy. So a person who only uses Jellymoon has no project on their second day, and one
who has never typed into a harness has none at all.

## What was added

- The ADR, two glossary terms (project, known project), the index row, and features F62 to F66 after F61. No
  existing row changed.
- The index row of ADR 0019 said "Proposed" after it was accepted: the word is removed.

## What the first builder must know

- **F62 is first and waits for `GATE: PASS`**: it changes where a run may start. One lookup serves `wishable` and
  a run, so what is offered is what starts.
- **A listed folder gets every check a typed-in folder gets**, each time it is used: it is there, it is a repo's
  top, it is the person's own, it is not switched off. The list is a file, and a file can be changed.
- **No path is printed**, by `project list` or anywhere else. Tests assert it.
- **Two folders of one name start nothing**, whichever of the day's typing and the list they come from.
- **Not confirmed**: what `jellymoon page` and the window show on a day with made wishes and nothing typed.
  `app.md` says only that such a day makes no reading call. F63's first test finds out.
- **F65 writes to the person's disk** and waits for a gate. Where its one folder is, is decided in F65 with the
  reason written down. Its first commit is made under the name a run commits under, so a person with no git
  identity can still start.
- F62 touches the run's lookup that F52 (`run answer`) also reads. Take F62 after F52 has landed.
