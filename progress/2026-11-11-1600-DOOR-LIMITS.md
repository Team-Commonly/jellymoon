# The door's limit is the one the docs state (PR 128, the gate on `f2a4210`)

- **The finding.** The docs said nine keys in a row are refused. Eight were, and a statement over 200 characters
  lost two more to the cut: the loop counted every cleaning, the one that confirms and the cut among them.
- **Fixed.** `still.rs` counts only cleanings that change the text: up to 8, then one that must change nothing.
  The cut is not counted; what it leaves is cleaned again within the same 8. Eight keys in a row are kept at any
  length and nine are not; 4096 bytes are cleaned and 4097 are not. `wish.md` and `delivery.md` say these numbers
  and `tests/f35/still.rs`, `tests/f37/still.rs` and `tests/f37/refused.rs` pin them at the binary.
- **No ruling of the mark.** `rule` and `settle` refuse a statement that cannot be cleaned, in one line, with
  nothing kept. A page still draws it as `[redacted]`; a tap on it in the app says "That tap did nothing." and why.
- **Evidence.** The six mutations the gate found alive, and two more (the cut counted, `rule` not refusing), each
  fail a test now. A ruling and a settlement's second statement from an earlier build have their own tests.
- **Surprise.** Counting the cut changes nothing unless the cut text changes afterwards, so its test needs a key
  id the cut ends.
