docs; nothing that ships. The review failed the door on two ways a test could still reach a person's own files or
programs, with eight notes. Nine findings are taken here and one (7) is named as a limit in `workflow.md`.

**What the door holds now** (the same list is in `workflow.md` and in ADR 0021, "Amended after the review of the
app's door").
- Folders, a full path under a temporary folder: `HOME`, `USERPROFILE`, `JELLYMOON_HOME`, `JELLYMOON_APP_DIR`,
  `JELLYMOON_BIN_DIR`, `CLAUDE_CONFIG_DIR`, `TMPDIR`, `TEMP`, `TMP`, `XDG_CONFIG_HOME`, `APPDATA`, `LOCALAPPDATA`.
- A file, with its folder: `GIT_CONFIG_GLOBAL`.
- Programs: `JELLYMOON_CLAUDE`; a `JELLYMOON_SHELL` that is named is a full path under a temporary folder.
- Lists of folders: no full-path folder of `PATH` or `JELLYMOON_SYSTEM_BIN` outside the temporary folders holds a
  `claude`, `claude.exe` or `claude.cmd`.
- Flags: `--logs`, `--settings`, `--repo`.
- A value that is no full path: each variable above and `--logs` is refused when it climbs with `..`, or as
  Windows reads it is rooted with no drive or has a drive and no root.
- A temporary folder is none when it is a root, or is or holds the home or the home's `.claude`, `.jellymoon` or
  `.local`.
- Set to nothing unless named: `JELLYMOON_SHELL`, `JELLYMOON_SYSTEM_BIN`.

**Worlds on main that changed.**
- F38 (`f38.rs`, `f38/limits.rs`) handed the door the whole `PATH` of the person running the tests. On a machine
  with Claude Code installed the door now refuses that, so the world takes git alone (`support::git_alone`, moved
  out of `f39/world.rs` and shared), and the made-up git stands before it.
- `f41/apart.rs` starts the made-up asker through `door::asker`: its name is now the door's alone.
- No world relied on a value that climbs. The worlds with a value that is no full path and stays in its folder
  still pass: `harness.rs` (`elsewhere`, `path`), `f39/safe.rs` (`harness`, `bin`), f74 (`user`, `.`, `~`) and
  f75 (`jm`, `user`).

**Sentences a person can read, added or changed.**
- `REFUSED`: "a test starts nothing in a world outside the temporary folders: the home, Jellymoon's folder,
  JELLYMOON_APP_DIR, JELLYMOON_BIN_DIR, CLAUDE_CONFIG_DIR, the temporary and config folders a world names, git's
  own config file, the login shell, a harness named with JELLYMOON_CLAUDE, --logs, --settings and --repo are each
  under the system's temporary folder (in the binary's tests /tmp on Unix too) or the one Cargo gives tests, none
  of those variables and no --logs climbs out of the folder it is read from, and no folder of PATH or
  JELLYMOON_SYSTEM_BIN outside them holds a claude", then "; this one named" and the name.
- `NO_ROOT`: "a test starts nothing: a temporary folder is a file system's root, or it is or holds the home of
  the person running the tests, or that home's .claude, .jellymoon or .local".
- `cargo xtask check`: its three sentences are as they were.

only that the `PATH` passes.

**Open.**
- Nothing here ran on Windows or Linux. The Windows readings are held as values on every system
  (`refusal_as(true, …)`), but a path with a drive and a root can only be resolved on Windows, and a `PATH` is
  split with the separator of the system the tests run on.
- `install.sh` takes `HOME`, `JELLYMOON_APP_DIR` and `JELLYMOON_BIN_DIR` as given. It should itself refuse one
  that is no full path, as `jellymoon uninstall` does. That is a change to what ships, so it is not made here.
- A `claude` in a temporary folder of `PATH` that is a link to a program outside is not refused: the door asks
  the folder, not where the name leads. No world plants one.
- A temporary folder under the home's `.claude` (not the folder itself) still passes, as the ruling words it.
- `search()` is now the look's name for the rule. A test of core that calls a function of that name by itself,
  with no path before it but `find::` or `super::`, would be refused; none does today.
- `crates/jellymoon/tests/f33.rs` has one test, for Linux only, that starts `sh install.sh` with `Command::new`
  and the process's own variables beside a scratch `HOME`. It was not in the review and is not changed.
