# STOPCANCEL progress (2026-11-09-0602 UTC)

**Changed.** #59 made `turn` in `daemon/internal/acp/acp.go` fail a run on a `refusal`, `max_tokens` or `max_turn_requests` stop reason. If a stop was already in flight (the client had sent `session/cancel`) and the agent answered with one of those instead of `cancelled`, the run ended `failed` rather than `cancelled`. `turn` now returns nil, before judging the reply, when `c.cancelling` is set; `Run` then reports the stop's cause (`errStopped` -> cancelled in `claim`; a deadline's cause stays its own and still fails). No change to `run.go`.

**Evidence.** `TestStopReasonDoesNotOutrankAStopInFlight` (three reasons x stop and deadline causes, fake agent mode `cancel:<reason>`) was red for all six cases (`Run = session/prompt: the agent stopped the turn with refusal, want stopped`) and is green after. `TestStopReasonDecidesTheTurn`, the replay tests and the rest of `go test ./daemon/... -count=1 -race` are green. The flag `cancelling` is only read and written by the goroutine that runs `Run`, `turn`, `call` and `serve` (the reader goroutine only moves messages over a channel), so no lock was needed and `-race` stays clean. The daemon LOC cap went 4,910 -> 4,940 (measured 4,934) with a note.
