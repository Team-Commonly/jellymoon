# F44: a finished run's work is shown, from the repo's store, with no folder and no diff

On branch `f44-show`, one commit on top of `068a6f4`. Not gated: it reads, and writes nothing. Design:
`docs/adr/0017-a-runs-work-is-shown-kept-or-tossed.md`; how it is built: `docs/development/show.md`. Tests: `crates/jellymoon/tests/f44.rs` and
`tests/f44/` (`file.rs`, `names.rs`, `refused.rs`), 22 tests; the two answers' shapes in core's `tests/shapes.rs`.

## What was built

- `jellymoon run show --wish <id> [--date] [--repo | --logs --skip]` prints the run, the wish, `work`
  (`waits`, `kept`, `tossed`) and up to 200 files, each with a number, a cleaned name, what was done to it, its
  size, what it is (`text`, `other`, `link`, `repo`) and whether tools obey it. `--file <n>` prints one file's
  text, cleaned until cleaning changes nothing and cut at 64 KiB before its last word.
- Core: `run/show.rs` (which run, the answers, the cleaning) and `copy/work.rs` (what is asked of git). Both go
  through `copy/git.rs`, so every switch a copy's git has is on, plus `--no-replace-objects`. A read stops at a
  stated size (`call::run_most`). No file name is ever an argument to git.
- The smoke chain has a `show` step after `run`, left out with `--real`: it asks for a page, which there is a
  second real reading call.

## What a run's record holds, and the rule chosen

`runs/<id>/run.json` holds the wish, the day, the outcome and the times: no repo, no start commit, no end
commit. The copy's record named the repo and is removed when a completed run's copy is cleaned. So:

- **The repo** is found as a run finds it: `--repo`, or the wish's project folder in the day's logs.
- **The work** is the tip of `refs/heads/jellymoon/run-<id>` against its one parent. The tip must be a commit
  with exactly one parent and the message `Jellymoon run <id>`. A branch that moved, is symbolic, names another
  kind of object or is missing is refused.
- Not closed: a commit made by hand with that message and one parent is shown as the run's. The record needs
  the repo, the start commit and the end commit to close it. That changes what a run writes at its end, so it
  is a gated change of its own, and F45 and F46 need it ("writes `kept` with the commit").
- `Record.work` was added as an optional field that is read and never written; a run's bytes are unchanged.

## Not measured

- Windows and Linux: nothing was run there. Only `cargo clippy --target x86_64-pc-windows-msvc` here.
- git other than 2.50.1 on macOS. A SHA-256 repo, a partial clone, a repo with a missing object.
- A git that stalls during a show: no made-up git test of the time limit on this path.
- The `for-each-ref` answer is not bounded by a size (it is one name's refs).
