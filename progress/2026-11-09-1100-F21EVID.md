# F21 EVID: the pod serves run evidence

**Governing ADRs (all Accepted; quoted as they stand).**
- 0006 as amended (`docs/adr/0006-pod-state-server.md:96-114`): "The server serves the `evidence` operation"; records are "Stamped by the pod, never written by an agent"; "A run keeps at most 500 records".
- 0002 (`docs/adr/0002-claims-and-leases.md:14-15`): "Its lease renews on (a) any operation that run's token makes, through any adapter". A read of evidence on a run token is such an operation.
- 0003 (`docs/adr/0003-pure-pod-core.md:53-57`): an ended run "gets `unauthorized` on EVERY command, before any other check"; a user "must be a member of the pod, or gets `forbidden` on every command, before `not_found`".
- 0003 (`docs/adr/0003-pure-pod-core.md:75-76`): "The core keeps only state; it keeps no messages." The records are in the server's own table.
- 0007 (`docs/adr/0007-agent-permission-and-cancel.md:17-19`): the daemon "does not log the tool call's title or input, which can hold a command line or a secret". That binds the daemon's log; a record's digest is the pod's own and is shown only to the run and to pod members.
- 0008 (`docs/adr/0008-github-sign-in.md:73-77`): the cookie reaches "every operation whose auth includes `user`"; the list now names `evidence`.

**Decisions.** The core is unchanged: it counts, and the adapter stores the record under the count it was given, once the call has an answer. So a call in flight has no record yet, the evidence call over MCP does not list itself, and a crash mid-call leaves a count with no record. Cap: the first 500 records of a run; the receipt keeps counting. Old saved state needs nothing: the table is created if missing, and a run from before has no records.

**Not in this unit.** The `ungrounded` refusal (F25), daemon-reported harness tool calls (F26), the Worker.
