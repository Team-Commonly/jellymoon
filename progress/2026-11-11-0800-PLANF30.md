# F30 is cut into F37 to F40, and a run is started headless (plan only, no code)

- **The design change** is `docs/adr/0014-a-run-is-started-headless.md`: a run is the person's harness started headless,
  not over ACP (the adapter is a Node package, which fails the install bar); what it may do is fixed at its start; a
  stop interrupts, signals, kills; core commits the copy with hooks off and the branch is kept. ADR 0011, section 7,
  is edited to match and points there.
- **The list.** F37 (`jellymoon wish`), F38 (`jellymoon copy`), F39 (`jellymoon run`, waits on F37 and F38), F40
  (`run stop`, waits on F39) are added. F30's entry is untouched.
- **An edge the list cannot hold: F30 waits on F40.** Only `passes` may change in an entry, so F30 still lists F28
  alone. Take F30 last, whatever the scoreboard offers.
- **Gates.** F39 and F40 change what leaves the machine and wait for `GATE: PASS`. F37 and F38 do not.
- **Not confirmed**, in the ADR's "Still open": a supported interrupt, Windows, hooks from a settings file, the
  protected paths. The flags were read from `--help` by the coordinator, never run by a worker.
- **Next.** F37 on branch `f37`; F38 can be built beside it.
