# Glossary

The words below mean exactly this in code, docs and tests. A new term is added here in the same PR that introduces it.

| Term | Meaning | Not to be confused with |
|---|---|---|
| **page** | One local day of one person's wishes, read from their agent sessions and shown by the app (ADR 0011) | a web page |
| **wish** | Something a person wants to exist or be true, worked out from what they typed to their agents; carries their own words and a state: working, done, needs you or let go | an ask, which needs a ruling |
| **little one** | The character that stands for one wish on a page | an agent |
| **star** | One finished job an agent reported for a wish | proof the job was done; it is the model's reading |
| **clash** | Two things one person said that cannot both stand. Shown as an ask; the person's tap is the ruling | a merge conflict |
| **ask** | A question put to the person with fixed options and an open decision | a question in prose |
| **ruling** | The person's choice on an ask, made by a tap and handed to each running session once. A tap the other way is a new ruling that replaces it | approval in chat |
| **settlement** | The file beside a day's kept page that says which statement of each clash stands, so the page draws it settled. No ruling is made from it | the ruling |
| **hook** | The one entry Jellymoon adds to the harness settings; the harness runs it at each step of a session, and it hands over the rulings that wait (`jellymoon hook`) | a git hook |
| **harness** | The agent program a person already uses: `claude-code` or `codex` | Jellymoon, which only reads its logs and calls it |
| **session log** | The file a harness writes for one session. Private, and untrusted input: it can hold any text an agent ever printed | page data, which code has checked |
| **turn** | One thing a person typed, with the agent's last reply to it | a line of a session log |
| **reader** | The part of core that collects one day of what the person typed from session logs (`jellymoon day`) | the reading call, which is the model's part |
| **reading call** | The one headless model call, through the person's own harness with every tool off, that proposes a day's wishes and clashes (`jellymoon page`) | the reader, which is code; a run |
| **page data** | What a page is drawn from: the day's wishes, stars and clashes after code has checked them. A typed shape in core | the reading call's raw reply |
| **core** | `crates/jellymoon-core`: every rule of the journal, with no UI | the `jellymoon` binary, which is core behind commands |
| **shell** | The app's window (`app/`): it draws page data with the kit and decides nothing | core; a login shell, which is the person's command program |
| **kit** | The fixed set of drawable pieces a page is arranged from (`crates/sticker-kit`). The model picks pieces; it never draws one | generated UI |
| **theme** | How a page looks: colours, fonts, paper, sizes and how much things move. Data only, never code and never a picture: the art is the kit's own | the kit, which is the pieces and their rules |
| **pack** | Extra pieces added to the kit as data and art only. None can be added yet, and a theme file is not one: a theme file names no art (ADR 0016) | a plugin, which would run code; a theme, which is how a page looks |
| **made wish** | A wish the person made in the app or with `jellymoon wish`, kept in their exact words beside the day's page and drawn with the reading's wishes | a wish the reading call worked out; a ruling |
| **run** | One agent session Jellymoon starts itself for a made wish: the person's harness, headless, in its own copy of the repo (ADR 0011, section 7; ADR 0014) | a session the person started, which Jellymoon only reads; the reading call, which has every tool off |
| **cancelled** | How a run ended that the person stopped with `jellymoon run stop`: no star, the copy kept, and the wish needs the person. A made wish gets one run, and that was it | failed, which is a run that ended badly by itself or was cut off |
| **copy** | A run's own working copy of the person's repo: a git worktree on a branch of its own. The folder is removed when the run ends; the branch, with the work on it, is kept until the work is kept or tossed | the person's checkout, which a run never touches |
| **work** | What a finished run made: the one commit on its branch, which waits until the person keeps it or tosses it (ADR 0017) | a star, which says a job was reported finished; the copy, which is the folder it was made in |
| **kept** | Work the person took with `jellymoon run keep`: it is one commit on the branch their checkout stands on, and the run's branch is gone | the copy being kept for a look, which is a failed run's folder left in place |
| **tossed** | What a run left, refused by the person with `jellymoon run toss`: the run's record says so, its branch is deleted while it is the run's own name at the commit the record names, the kept copy of a run that did not finish is removed, and the wish is let go | cancelled, which is how a run ended; let go, which is the wish's state |
| **question** | One line a run's agent ends a turn with when it cannot go on without a fact: an agent's text, cleaned and drawn as text. The run has not ended; it asks (ADR 0018) | a permission request, which no run makes; a ruling's ask |
| **a run that asks** | A run whose harness ended its turn with the state `asks` and one question that passed the door: its record's outcome is `asks`, its copy stays as the agent left it with nothing committed, nothing holds it, and its wish needs the person and carries the question. It has not ended, and is neither going nor cut off (`run.md`, "A run that asks") | a failed run, whose copy is kept for a look; a cancelled run |
| **last word** | What a run's harness ends its turn with as data, under a schema: the state `done`, or the state `asks` with one question. Core reads it from the stream's result and nothing from the agent's prose | the result's text, which is never read |
| **result** | What a finished run says of its own work, as data in its last word: a short list of pieces. Core keeps it beside the run's record, checks every piece against the work at each look, and prints what passed (`run show`); a page draws it over the note of work that waits (ADR 0023) | the stream's result line, which is the harness's; the work, which is the commit; a star |
| **piece** (of a result) | One part of a result, of a kind from a closed list: `did`, `change`, `decided`, `unsure`. It is the run's words, drawn as quoted words only, and one that fails its check is dropped whole (ADR 0023) | a piece of the kit, which is something a page is drawn from; a file of the work |
| **try command** | The one command a person named for a known project (`jellymoon project try <name> --with ...`): a program and its arguments as plain words, kept on the project's line of the list and never in the repo. Naming it is the person's yes to its being run on every run's work there (ADR 0024) | the harness's command line, which is Jellymoon's; a command of `jellymoon`; anything a run or a model wrote |
| **try** | One running of a project's try command on a run's work, by core, in the run's copy, after the work is committed and before it waits. How it ended (`passed`, `failed`, `too_long`, `not_started`, `stopped`) is core's own fact, kept in the run's record as `tried`; what the command printed is untrusted text (ADR 0024) | a run, which is a harness at work on a wish; `Show me`, which shows the work and starts nothing; a piece of a result, which is the run's say-so |
| **answer** | The words the person gives a run that asks, with `jellymoon run answer`; they go on with the same run | a made wish, which starts a run; a ruling |
| **follow-up** | A made wish that names the wish it follows ("more like this"): a new run on the followed work, or after a run that changed nothing, with a fork of its session (ADR 0018) | an answer, which goes on with the same run |
| **key** | The one key combination Jellymoon registers with the system. Held anywhere, with the app not in front, the ear listens; let go, it stops (ADR 0019) | a key typed into the page's entry; a credential |
| **ear** | The part that turns what is said while the key is held into words, on the machine (`crates/ear`). It returns text or one of a closed list of refusals, sends no sound anywhere, and decides nothing | the reader, which reads session logs; the reading call |
| **heard wish** | Words the ear returned for one hold, once they passed the door a typed wish passes. It is shown for four seconds and is kept nowhere; then it is made a wish, unless the person took it back | a made wish, which is kept and cannot be taken back |
| **taken back** | A heard wish the person dropped by pressing the key again before its four seconds ended: nothing was written and nothing started | tossed, which refuses what a run left; cancelled, which is how a run ended |
| **jellyfish** | The small window at the screen's edge that shows, in core's words, what is being heard and what the runs are doing. It takes no keys; a tap on it opens the page | a little one, which stands for one wish on a page; the shell's page window |
| **bubble** | The second small window beside the jellyfish, open only while it has words: the words so far, a heard wish with its ring, a run's question, or a refusal. It takes no tap (ADR 0019) | a note, which is a piece of a page; the typed words on a page, which the kit draws as a quote piece |
| **step** | One use of one of a run's five tools that core read from its stream while it works: the tool, and for `Edit`, `Read` and `Write` the cleaned name of a file in the run's copy. Every step is counted and the last 4 are kept, in `runs/<id>/steps.json` (live work, `docs/development/run.md`) | a tool's input or result, which is never kept; a stage of the loop |
| **say** (a little one's) | The few fixed words on a small pill over a working made wish's little one: the stage its run is at ("looking around", "making the change"), or "thinking" before the first step. It names no file and takes no tap | the bubble, which is the jellyfish's second window; a note |
| **edge scene** | The kit's data for what stands at a screen's edge: a character with a mood, a bubble of texts and a ring. It knows nothing of Jellymoon; the app fills it from core's `JellyDrawn` (`crates/sticker-kit/src/edge.rs`) | a scene, which is a page's pieces |
| **page's day** | The day the page in the app's window shows: the day the app was opened on, or the day `--date` named, until the person moves the page on by a tap (ADR 0022) | today, which the clock gives and the page's day may be behind |
| **quiet** (a day) | A day for which core's look for the jellyfish gives `quiet`: no question waits, no run is at work and no work waits to be kept or tossed. Only a quiet page's day is offered a move (ADR 0022) | settled, which a clash is by its settlement; a day with no made wish, which is quiet too |
| **project** | A repo's top folder, called by its last name. A wish is made for one, and a run works in a copy of it | the folder's path, which is the person's and is never printed; a page |
| **known project** | A project on the list Jellymoon keeps in its own folder: a run started in it, or the person named it or made it with `project new`, as a folder in `projects` in Jellymoon's own folder (ADR 0020). It is offered on a day nothing was typed in it | a project typed in that day, which is offered with no list |
| **made project** | A known project Jellymoon made with `project new`: a folder of the project's name in `projects` in Jellymoon's own folder, a repo whose first commit holds no file. It is listed, offered and forgotten as any known project is, and `project forget` and `uninstall` leave its folder | a project the person named with `project add`, whose folder is wherever they keep it |
| **list of projects** | The one file of known projects, `projects.json` in Jellymoon's own folder: a line for each, with its name, its folder and the day it was last used. A name has one folder. It is read as untrusted and never printed with a folder (`docs/development/project.md`) | the day's typed-in folders, which the reader finds in session logs; made wishes, which are kept by day |
| **stands** (a listed folder) | A listed folder a run may start in now: it is there by the path that was listed and through no link, holds a `.git`, is the person's own and is not switched off. It is asked each time the name is looked up; one that does not stand stays listed and is not offered | stands (a statement), the side of a clash that a ruling keeps |
| **hold** | One press of the key to its letting go, or to 60 seconds. Under 300 ms it is a slip of the hand and hears nothing; else the ear's final words for it are its heard wish (ADR 0019, `docs/development/hear.md`) | a lock that is held; a kept copy |
| **hearing** | Core's part of voice from its start to its end: given key, ear and tick events, it says what the jellyfish shows, and makes a heard wish a wish. `jellymoon hear` is one, and the app holds one (`hear.rs`) | the ear, which turns sound into words; a reading, which is a call to a model |
| **session store** | The harness's own folder of session logs: a folder for each project, a file for each session. Jellymoon reads it, and never writes, moves or removes anything in it (ADR 0018, ADR 0021) | Jellymoon's folder, which holds its own files; a run's record |
| **shim** | A small script a version manager leaves under a program's name, which starts the real program. Jellymoon starts one as it starts any harness, and never reads it to guess the program it names (ADR 0021) | the hook; a link, which the system follows |
| **Jellymoon's log** | `app.log` in Jellymoon's folder, and the one older file beside it: times, codes, fixed sentences, numbers and kinds from a closed list, bounded, with no name of a file, folder or project and nothing the person typed. A refusal and the hook write no line (ADR 0021) | a session log, which a harness writes and is private |
| **login shell** | The person's command program (`zsh`, `bash`), started interactive and with no terminal. Jellymoon asks it for its `PATH` when the harness is in no listed place, reads the one line between two marks and runs nothing it prints (ADR 0021) | the shell, which is the app's window |
| **feature** | One entry of `feature_list.json`: a test at the binary's boundary that defines done | an issue |
| **unit** | One piece of work given to one worker: usually one feature, and one file in `progress/` | a feature, though often one-to-one |
| **column** | What a page is in the window: one run of pieces read from its top, as long as what it holds, the newest at its end. The header, a row for each wish of the reading, the day's own notes, then each made wish's typed words over its notes (ADR 0026) | a column of a grid: a page has one and no grid |
| **card** | A note as the column draws it: one width, as high as what it holds, under the card before it. Never moved beside another, made smaller or left out for room (ADR 0026) | a wish; a row of a list |
| **typed words** | What the person typed for a made wish, on the page as theirs: the kit's `Note::Said`, id `typed-<wish>`, at the column's right with the wish's little one at its end, drawn by the rules for quoted words. A tap on them is a tap on that little one (ADR 0026) | `said-<wish>`, the note that answers a tap on a wish's work; the bubble, which is a window |
| **band** | The strip at the window's bottom that holds the entry. It is the window's and not the column's: it never scrolls and no card is drawn or tapped under it (ADR 0026) | the footer, which is a line under the page's title |
