# The obeyed mark reads a name as the disks read it

On branch `obeyed-fold`, one commit on top of `389aea7`. It fixes one blocking finding of the review of F44
(PR 158): `run show` printed `"obeyed": false` for work whose name a disk opens as `.cursor/`, `.claude/` and
the like. How it is built and what was measured: `docs/development/show.md`, "Files the person's tools obey".
`feature_list.json` is unchanged.

## What was built

- The rule and its list moved out of `run/show.rs` into `crates/jellymoon-core/src/run/obeyed.rs`. `show.rs`
  keeps the two asks (the name as git keeps it, and the cleaned name) and one `use`.
- A path is parted at `/` and `\`. Each part is cut at a `:`, loses the sixteen characters HFS+ leaves out,
  has each character APFS takes for ASCII letters made those letters (and `ı`, for NTFS), loses the dots and
  spaces at its end, and is compared in any ASCII case. A part with `~` and a digit is marked as a short name.
- The list is one const of 19 names: the 13 there were, `.cursorrules`, `.pre-commit-config.yaml`, `.cargo`,
  `GEMINI.md`, and two names of two folders, `.github/workflows` (it was a const of its own) and
  `.github/copilot-instructions.md`.
- No new dependency.

## What the disk said

A script made files and asked the disk, for 63,982 code points (U+0001 to U+FFFF but `/` and the surrogates,
and U+E0000 to U+E01EF), on this Mac's APFS volume and on a 100 MB HFS+ image mounted under `target/`, then
detached and deleted.

| Asked | APFS | HFS+ |
|---|---|---|
| one character taken for one of `a`-`z`, `0`-`9`, `.`, `-`, `_` | U+017F `s`, U+212A `k` | none |
| one character taken for two or three of them | U+00DF and U+1E9E `ss`; U+FB00 `ff`, U+FB01 `fi`, U+FB02 `fl`, U+FB03 `ffi`, U+FB04 `ffl`, U+FB05 and U+FB06 `st` | none |
| a character left out of a name (first, inside, last) | none | U+200C to U+200F, U+202A to U+202E, U+206A to U+206F, U+FEFF |
| a dot or space at the end, a `\`, a `:` | kept | kept |
| code points the disk would not make a name of | 1,529 (the first is U+0378) | none |

The review had the two single letters and the two joiners. The ligatures were new: `.github/workﬂows/`,
`.pre-commit-conﬁg.yaml` and `.github/copilot-inﬆructions.md` open as the plain names on APFS.

## Tests, and whether each was red first

At the binary, `crates/jellymoon/tests/f44/obeyed.rs`, four tests. Three were red against `389aea7`
(the Mac spellings, the Windows spellings, the new names and near misses). The fourth, a name the tools obey
past the 200 characters that are printed, was green before: it holds the ask of the name as git keeps it, which
no test held.

In core, `run/obeyed/tests.rs`, written with the rule: the old table test, moved; every name of the list; every
spelling the measuring found; the Windows spellings; the near misses; and two that run only on a Mac and ask
the disk (every obeyed name in every spelling the table knows, and every measured code point against every name
of one and two ASCII characters, `ffi`, `ffl` and `xy`).

## Mutations: 36, one at a time, each against core's obeyed tests and F44's at the binary

| Mutation | Core | Binary |
|---|---|---|
| each of the 12 folds removed (U+017F, U+212A, U+00DF, U+1E9E, U+FB00 to U+FB06, U+0131) | all killed | 7 killed; U+00DF, U+1E9E, U+FB00, U+FB03, U+FB04 survive |
| each of the 4 ranges left out removed, and U+200C or U+206F alone | all killed | U+200C to U+200F and U+200C killed; the other four survive |
| `\` does not part a path | killed | killed |
| ends not dropped; a space kept; a dot kept | killed | killed |
| not cut at `:` | killed | killed |
| short names not marked; no digit needed; no `~` needed | killed | killed |
| each of the 5 new names removed | killed | killed |
| the name as git keeps it not asked | survives | killed |
| the cleaned name not asked | survives | killed |
| a pair obeyed by its second name alone; a pair asked only at an even place | killed | killed |
| case not folded | killed | killed |

First pass: U+FB03 and U+FB04 were killed in core only by the table; the disk test now makes `ffi` and `ffl`.
"No `~` needed" survived core, "no digit needed" and "a pair at an even place" survived the binary, U+FB05 the
binary: each got a case and was killed on a second pass.

Survivors, with the reason:

- **Five folds at the binary** (`ss`, `ff`, `ffi`, `ffl`): no obeyed name holds those letters, so no file name
  can show them. Core kills each, from the disk.
- **U+202A to U+202E, U+206A to U+206F, U+FEFF at the binary**: cleaning takes those out of the printed name,
  and the cleaned name is asked too, so the mark does not change. Core kills each.
- **The two asks in core**: they are in `show.rs`'s `entry`, which only the binary's tests reach.

## Not measured

- Windows: nothing was run. `\`, `:`, the ends, `ı` and the short names are reasoned. NTFS's table of capitals
  was not searched for other characters it takes for an ASCII letter.
- A case-sensitive APFS or HFS+ volume; HFS+ on a disk rather than an image; a character above U+FFFF other
  than U+E0000 to U+E01EF; one character taken for four or more; ext4 with case folding, exFAT, SMB, NFS.
- The test that runs on every `cargo test` asks only the disk the temporary folder is on (APFS here). The HFS+
  findings are held by the table test.
- The one probe run of every three-character name on APFS took 76 s, over the 60 s it was allowed.
