How Room scales

The room view failed four ways in the last round: crowding, keyboard, state carried only by pose, and motion. Here is what this build does about each.

Past about 8 members: zones

Above 8 members the floor groups desks into zones, by task or by owner. A collapsed zone still shows its counts by state, so a waiting lamp is never hidden. Zones that hold a waiting member open by default.

Keyboard

Every desk is a real button with a visible focus ring.

State as text

Each desk states its lease in words, in a visible caption and in the button’s accessible name (“State: Waiting on you”). The pose only repeats it. Tests assert the text and never the drawing, for example getByRole('button', {name: /Otto.*State: Waiting on you/}).

Reduced motion

Typing hands, the lamp wave and blinking all stop under prefers-reduced-motion, and so do zone, popover and scroll transitions. The dawn texture behind the round table header is removed there and under prefers-contrast: more. No state depends on motion.
