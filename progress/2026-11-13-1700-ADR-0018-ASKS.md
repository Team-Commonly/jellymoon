# ADR 0018: a run asks, and is told more

Branch `adr-18`, written on `main` at `11fd1d8`. Docs and feature rows only: no code.

## What was decided

`docs/adr/0018-a-run-asks-and-is-told-more.md`. In one line: a question ends the harness with its question as
data, and an answer or a follow-up starts a new process that resumes the run's kept session by its id.

- The harness's own flags carry it: `--session-id`, `--resume`, `--fork-session`, `--json-schema`. No hook, no MCP
  server, no permission tool and no process held open.
- A run's session is now kept, which ADR 0014 had ruled out. The reader must leave out a run's copy first, or the
  wish and every answer come back on the next page as typed turns. That is F50, and it is built before F51.
- A follow-up is a new made wish with its own one run. Keeping and tossing go in order (decision 9).

## What was measured, and how

On Claude Code 2.1.323, in a scratch repo, by the coordinator, with a made-up task: a run that asked and changed
nothing; an answer given to a second process; a follow-up in a second worktree after the first was removed; a
resume of an id nothing has; and the shape of the two session files, which the reader's rule would keep. The
probe's two session folders were removed from the harness's store afterwards. The ADR's "Measured" has the
results and "Not measured" has what was left.
