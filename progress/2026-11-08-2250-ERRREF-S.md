# ERRREF-S

A refused ruling's `error` frame now carries `ref`, the id of the decision the ruling was about, so the web store can put the error on that card.

- The shared rule (`podcore/src/rule.ts`) already put `decisionId` on its `not_found` and `already_ruled` refusals through `fail(..., ref)`; the two adapters dropped it when they rebuilt the frame body as `{ code, message }`.
- Fix: both adapters (`server/src/ws.ts`, `worker/src/pod-do.ts`) copy `ref` through when the refusal has one. No adapter-only logic, no schema change (`ErrorBody.ref` exists). Every other error frame has no `ref`, as before.
- Tests, one file per adapter (`server/test/ruling-ref.test.ts` over a real socket, `worker/test/ruling-ref.test.ts` over the pod object): a ruling on an unknown decision returns `ref` equal to its id; a malformed `message.post` returns an error with no `ref`. Red before the fix, green after.
- Mutants: dropping `ref` in the server adapter, then in the worker adapter, each fails its ruling test.
