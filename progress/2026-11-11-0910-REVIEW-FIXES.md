# The seven findings of the reviews of F38 and F37, in one change

- **Done.** `copy make` takes a repo only at its top by its real path. Cleaning a text twice is cleaning it once. A
  folder in `copies` that no run stands for goes at the next clean. The run that just failed is always kept, and
  `kept` is read after the old ones went. Each `protocol.<name>.allow` the config names is set to `never`. Two tests
  and two corrected docs for the made wishes' note. Each has a test that failed first.
- **Decided.** Cleaning is fixed by its order, not by a loop: the text is laid out before a key shape is looked for.
  A link to a repo's top is that repo. A stopped git's children are not killed (no process-group call in std, no
  unsafe); what they write is removed afterwards. A made wish's note is not counted where it would move a clash.
- **Surprises.** Two more ways a cleaned text changed when cleaned again, found by the test of built texts: the `]`
  of a replaced path segment ended the path, and a word cut after an AWS key id's twenty characters became one.
- **Next.** This changes redaction, so it waits for `GATE: PASS`. Open: the joiners U+200C and U+200D inside a key
  still hide it, and the test of built texts does not reach a text over the 16,384-character window.
