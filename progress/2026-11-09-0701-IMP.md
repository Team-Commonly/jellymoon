# IMP: `jellymoon import commonly`, agent cards, grants checklist, and ADR 0004 ratified

**Governing ADRs (all Accepted; quoted as they stand).**
- 0003 (`docs/adr/0003-pure-pod-core.md:18-19`): "Authorization is decided from state… Actors arrive already authenticated and stamped; the core never trusts a role in the input." The importer is outside the core and sends no role; it uses the caller's own token.
- 0006 (`docs/adr/0006-pod-state-server.md:19`): "An adapter. It does I/O, persistence, the timer, fan-out and the `sinceSeq` log. It decides no rule". No server change was made.
- 0008 (`docs/adr/0008-*.md:42`): "The token never reaches argv, stdout, stderr or a log." The Commonly token comes from the environment or a hidden prompt, and the redactor now also shortens `cm_` tokens.
- 0009 (`docs/adr/0009-connector-layer.md:59`): "OAuth… is out of this slice: the owner pastes a token." Grants are only listed; no vendor but Linear is marked supported.
- 0004 (`docs/adr/0004-open-core-boundary.md:21-22`): "Never in `ee/`: … the CLI …". The command lives in `daemon/internal/cli`, outside `ee/`.

**Decisions.** A scrub failure leaves nothing written, because every pod is read and scrubbed before the first write. The five-failure stop happens in the read phase, so the saved state is unchanged; in `--apply` a lost answer is reconciled from the marker line. The dry run writes no file. The owner's grants list is used, not the per-pod route, so cards carry no description. All redirects are refused, stricter than "cross-host". Agents are registered by `jellymoon agent add`, as there is no `agent register`.

**Evidence.** Unit tests were red (the package did not compile) and e2e was red (the command printed its usage) before the code; both green after. `e2e/imp_test.go` runs a fixture Commonly and a real local Jellymoon: a DM is skipped and an unjoined agent-dm never read; an admin token is refused after one request; a planted `cm_` string fails with exit 1 and no write and no state file; no `scope`, no forbidden route, only GETs with the token; the token appears in no output, file or request; apply twice posts nothing the second time; a kill after the second post resumes with no gap or duplicate; 429 then 503 wait with one request in flight.
