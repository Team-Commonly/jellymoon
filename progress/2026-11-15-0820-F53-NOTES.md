## What changed

- **A lost fork is started again only in a copy that stands on the run's branch.** `copy::as_made`
  (`copy/clean.rs`) also asks `symbolic-ref --quiet HEAD` of the copy and wants the run's branch. A fork that
  left the branch, committed and then said its session is lost has failed, in the words of a fork that worked.
- **The made-up agent can be lent the real git.** A test writes its full path to `rec/git`, and the `unkept`
  script's numbers 4 to 7 then work in the copy before they say lost (`tests/support/fake_agent/follow.rs`,
  `worked`): a commit on the run's branch, one file an exclude names, a commit on no branch, a commit on a
  branch the fork made. Each is played in `tests/f53/notes.rs`.
- **`jellymoon run toss` lets go a made wish that has had no run** (`run/unrun.rs`). The kept wish takes
  `let_go` and the line `the wish had no run, and was let go`, behind the day's lock; no record, copy, branch
  or repo is read or written. It prints a toss's five names with `run` and `commit` both `null`, so `Tossed`'s
  `run` is an `Option` now (example `tossed-unrun.json`). It holds the keeps' lock as every toss does.
- **No run is started for a wish that was let go.** `jellymoon run` refuses it before it looks for a harness
  or a folder, and a run's start refuses it where it writes its name in the wish, behind the day's lock: of a
  toss and a start of one wish, the one that had the day's lock first is done.
- **The object replacement character has a work of its own** in the made-up agent (`object`), which `tests/f47.rs`
  reads: without U+FFFC on core's list that work is plain.
- **Words.** show.md says by whose tables a code point is "not assigned", names three shapes of a count that
  are plain, and says `the keep compares no name` and `in its history`; so does `run/waits.rs`.

## What the next session should know: open rows

1. A wish that was let go is one of the day's eight still, with or without a run: a made wish's id is its
   place in the day's file. Whether a day should hold eight wishes that are not let go is not decided.
2. The app has no way to let a wish with no run go: a page offers `Toss it` only under work that waits.
   `work_tapped` was not changed.
3. `run_apart` does not ask whether a wish was let go: the command it starts refuses, and the caller is told
   that command's line. No test plays it, since `wish --run` starts a run only for a wish it has just made.
4. The order of tosses asks nothing of a wish with no run. With `after` written into a kept wish by hand, a
   wish with no run can be named as followed; nothing reads that.
5. The shape of a count is a decimal digit, then spaces or none, then `more`. Plain, and so with a yes on a
   page: a number that is no decimal digit (`+⑤ more`, `+Ⅴ more`), a number in words (`+five more`), and a
   separator that is not a space (`+5·more`). Read from the pattern in `run/obeyed.rs`; none was played.
6. "Not assigned" is by the `regex` crate's tables, Unicode 16. A name with a letter Unicode gave out later
   has no yes on a page until those tables know it. It fails closed.
7. The smoke chain was not run for this change: it builds the app. The app's tests were not run either, and
   the app builds the made-up agent this change adds scripts to.
8. Of `2026-11-15-0306-F53-FOLLOW-UP.md`: rows 1 (the fork on a real harness), 3 (the order of a toss is read
   from the day's made wishes), 5, 6 and 7 are open as written there. Rows 2 and 4 are closed here.
