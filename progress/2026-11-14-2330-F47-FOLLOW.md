# F47: what its third gate left

On branch `f47-follow`, on main `1a41d53`. The account is ADR 0017, "Found while building F47", point 9,
`docs/development/show.md` ("What is said of each", "A keep from a page"), `app.md` and `keep.md` step 5.

## What changed

- **A name is plain only when a person reads it as git keeps it** (`run/obeyed.rs`, `plain`). Not plain, though
  printed whole: a letter that draws as nothing or as a blank, a joiner, a space nobody sees, and a name that
  reads like a note's count (a digit and then `more`). Such work has no yes on a page, as before for a name
  cleaning changed.
- **The kit** places a text note's options only under a title and a body both drawn whole.
- **One check of a page's yes.** `work_tapped` no longer compares the note's words before the keep. The keep is
  given the names the tap carried and checks them under its lock. Two mutations that lived are dead by this:
  handing the keep the names read at the tap, and telling `landed` that no check is of the work's own files.
  Both fail `app/tests/f47/named.rs`, at the app's boundary; no unit test was added for them.
- A yes to other names is now refused in the keep's sentence ("..., as it would land in your checkout, are not
  the ones a note named, ..."). The sentence `work_tapped` had for it is gone.

## What the next session should know: open rows

1. The list of letters that draw as nothing is a list. A letter no font on the machine has and a mark that
   combines with the letter before it are not in it. Letters written right to left are plain; how a name that
   mixes both directions is drawn was not looked at.
2. A count is refused by its shape anywhere in a name, so `7 morels/CLAUDE.md` has no yes on a page.
3. Two names that differ only by letters that look alike (Latin `a`, Cyrillic `а`) are both plain.
4. A title that is cut leaves the note with no choice and no sentence that says why, as names that do not fit do.
5. The open rows of `2026-11-14-0400-F47-SECOND-GATE-FIX.md` that are left there.
6. The shape of a count is a decimal digit and then `more` in Latin letters. A name that reads as a count in
   another script's digits is refused; one with `more` written in letters that only look Latin is not.
7. A long name wraps, and its last line can read like an option's label (`Keep it`). The option is drawn as a
   button below the names and a name is not; nothing else tells them apart.

## What its own gate found

The gate of this PR failed it on two findings, fixed on the same branch.

- **One list of what is not read in a printed text**, `redact.rs`, `holds_unseen`. A name is held to it, as a
  refused `voice.toml` value was. It gained the object replacement character and every code point that is
  private or not assigned: a system font drew `.claude/settings`, U+F860, `.json` as the settings file's own
  name, and a tap kept it. `obeyed.rs` keeps only what is a name's alone: a space at an end of a folder's name
  and the shape of a count.
- **A yes to other names is not refused where the person's branch holds the run's commit already.** A keep
  answers that nothing was landed before it looks at any name, as `run keep` does. The three sentences that
  said "refused, with nothing changed" (`show.md`, `app.md`, `work_tapped`) now say so, and
  `app/tests/f47/named.rs` plays it.
