# F74: the door a test starts `jellymoon` through

**What changed.** On branch `f74-door`, on main `06b9bec`. Tests, their support and xtask; nothing that ships.

- **The door** is `crates/jellymoon/tests/support/door.rs`. `door::jellymoon` and `door::command` make the command
  a test starts; `door::refusal` is the rule. A world whose `HOME`, `USERPROFILE`, `JELLYMOON_HOME`,
  `CLAUDE_CONFIG_DIR`, or value of `--logs`, `--settings` or `--repo` (after the flag or joined with `=`) is a
  full path outside the temporary folders is refused by a panic, as the support's other failures are, before any
  program is made. Both sides are link-resolved as far as the path is there: the longest start that is there as
  the system resolves it, a link whose end is not there read in turn (32 at most), and `..` worked out in the
  rest. No home, an empty one and one that is no full path pass.
- **`JELLYMOON_SHELL`** is set to nothing in every command the door makes. A test may name a full path under a
  temporary folder; any other value is refused. Nothing reads it yet (F78). The smoke chain's made-up world sets
  it too (`smoke.rs`, `alone`, used at its three places that clear the variables).
- **Moved through the door.** Direct starts: `World::going` (`f39/world.rs`), `fed` (`f52.rs`), `hearing`
  (`f55/started.rs`), beside the support's own `started`. Through another program: the hook's entry (`f29.rs`),
  the installer and the installed command (`f33.rs`, `Mac::command`), the made-up asker (`f41/apart.rs`). The
  copy under another name (`f35/delivery.rs`) is never started by the test; it takes the path from
  `door::built()`. Seven worlds made with `tempfile` by hand take `support::system_scratch`, and one
  `kept_scratch`.
- **The rule** is `crates/xtask/src/rules/door.rs`, run by `cargo xtask check`: by file and line, a test file of
  the binary outside `support/` that names the built program or makes a temporary folder, and a test in core
  that has the harness looked for with the process's own environment. What it cannot see is in
  `docs/development/workflow.md`.

**Decided.**
- **`/tmp` is a temporary folder of the system's** beside the one the process is given, where there is one.
  Four tests gave the root folder (or `/usr`) as the home, to have a home of another owner (`f35/delivery.rs`,
  `f41/refused.rs`, `f62/refused.rs` for two tests). The door refuses the root folder, and on a Mac the
  process's own temporary folder is the person's. `/tmp` is the one folder a test can name that is someone
  else's, so those tests assert what they asserted (`door::not_ours`). ADR 0021 did not list them.
- A refusal is the fixed sentence, then "; this one named" and the variable's or the flag's name. Never a path.
- `HOME` and `USERPROFILE` are both checked on every system.

**The evidence.** Red first: with the rule of `refusal` and the set of `JELLYMOON_SHELL` taken out, 6 of the 7
tests of `tests/f74.rs` failed (the seventh is the worlds that pass); with the xtask rule reading no file and
the smoke world not setting the variable, 5 tests of xtask failed. 45 one-rule mutations (25 of the door, 19 of
the rule, 1 of the smoke world), each seen to fail a test. Lines: 25203 for the binary (from 24854), 2591 for
xtask (from 2426).

**Open.**
- The ignored test of F29 that runs the real Claude Code starts it with the person's own variables. By design,
  and not through the door.
- `the_install_script_refuses_a_system_that_is_not_a_mac` (`f33.rs`, Linux only) starts `sh` with the process's
  variables and a scratch home. The script stops before anything is installed. Not moved: it cannot be run here.
- The smoke chain's `--real` mode and its window step keep the person's variables, as before.
- The rule reads lines. A program started from a path read out of a file, or from `door::built()` with
  `Command::new`, is not seen.
- Not run: Windows and Linux. On Windows a link needs a right most users lack; the link test says so and
  returns. `door::not_ours` is none there.
- ADR 0021, decision 7, says "a test hands the look its variables". Core's look takes none: it reads the
  process's. No test in core calls it today, which is what the rule holds.
