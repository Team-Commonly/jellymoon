# F54: a question is answered, and more is asked for, in the window

**What changed.** On branch `f54-answer`, on main `3fa9354` (F57, `a22bccd`, is not joined in). A made wish's
note can have a field under it. A wish whose run asks is drawn with the question, as someone else's words, and
a field; Enter there gives the words to core's `answer_run`. A wish whose work waits or was kept has `More like
this` over a field; Enter there gives the words to core's `wish_after`, and the follow-up's run is asked for as
a typed wish's is. Every refusal drawn is core's sentence. How it works is `docs/development/app.md`, "A
question answered, and more like this"; what was decided is ADR 0018, "Found while building F54". F54 is
`passes: true`.

- Core: `followable(home, day)` and the key `follows` in `jellymoon run waiting`. No rule of a run changed.
- Kit: a text note's `quoted` words and `field` (`layout/typed.rs`, `draw/field.rs`); the entry's input handler
  moved to `draw/input.rs`. Pieces `quote`, `field`, `offer`.
- App: `answering.rs`; `working.rs` puts the field where core says; `window.rs` routes an Enter by the id the
  kit gives (11 lines, in `entered`).

**The evidence.** `cargo test -p jellymoon-app --test f54` with the two headless features (16 tests),
`cargo test -p jellymoon --test f54` (2), the kit's `tests/typed.rs` (5) and `tests/field_draw.rs` (3).

Seen red first: the binary's test (`run waiting` printed two keys, and no `follows`), and the app's layout
tests (4 of 5 failed for a missing `quote`, `field` and `offer` piece). The app's `answered.rs` and `more.rs`
and the kit's tests were written before their first run and after the code, so they were not seen red: 30
one-rule mutations stand in, each seen to fail a test. One lived at first (work that waits drawn a second time,
as a wish that stands) and got an assertion in `f54/drawn.rs`.

**Surprising.**
- `cargo xtask check` counts tracked files only: new files count once they are staged.
- The made-up agent's `slow` script changes nothing, so its wish has no work to follow when it ends.
- A follow-up's run needs the agent's `follow` script: `edits` removes a file the followed work removed already.
- A piece with the id `me` stands among the characters; a made wish's is `m` and a number.

**Open.**
- An answered run lives in the app's process: a window closed before its end leaves a run that was cut off.
  Closing it needs a `run answer` started apart, which is a new rule of a run.
- A field takes 400 characters (the kit's cap on a line); core takes an answer of 600.
- The offer stands over its field, on a line of its own, not beside the choices.
- In the window one wish is open at a time, so of two wishes that ask one is on show; `layout` prints both.
- A note left on show while its wish changed elsewhere keeps its field; core refuses an Enter there in its words.
- A field's element stands where the layout placed it and does not follow its note while the note moves in.
- Not run: Windows and Linux, a real window, a real harness, `make preflight`.

**Budgets.** Core 14491 to 14507, the binary 24489 to 24587, the kit 8439 to 9026, the app 8437 to 9309; xtask
is unchanged.

**Joined onto `b5b91c5`.** The commit was made on `3fa9354` and is cherry-picked onto main `b5b91c5` (F57, the
notes after F53 and on F63) as branch `f54-join`; that is its true parent. Six files conflicted. The join added
one rule: a note's field answered while the page's window is closed is answered all the same
(`Page::answer_field_closed` in the kit, `tests/field_draw.rs`; `answer_entry` in `app/src/window.rs` takes the
field's note). The kit's `entry_changed` tells the platform of the line with the keys and then settles, and
`entry_settled` settles with no window. The sentence in `app.md` about "Read from 0 things you typed" went:
main's footer says it now. The budgets are the joined tree's own, in `entropy.toml`.
