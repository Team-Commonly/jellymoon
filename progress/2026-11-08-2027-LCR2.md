# LCR2: a clean CodeRabbit re-review satisfies land's check (c)

**Changed.** When CodeRabbit re-reviews a head and finds nothing, it files no PR review and only edits its summary comment, so
check (c) refused a clean fix head ("CodeRabbit has not reviewed d5ca0091" on PR 13). Land now has a second, fail-closed way to
meet (c): exactly one CodeRabbit-authored issue comment with exactly one `final_review_risk_coverage` marker whose source and
covered ids both equal the head and whose kind is `reviewed`, plus the line `No actionable comments were generated in the
recent review.` on a line of its own outside HTML comments. A `CHANGES_REQUESTED` review at the head still refuses. Land reads the
issue comments only when no submitted review settles (c). The result says which way (c) was met, and the note adds
"(summary comment)" for the new way.

**Evidence.** The cases were committed red first (8 of 97 failed). The 11 mutants of the new path are each caught. The real PR 13
comment, trimmed, is the fixture; a read-only run against PR 13 at d5ca0091 says ok.

**Next.** `scripts/check-land-e2e.mjs` has no route for the issue-comments read, so no end-to-end case covers the new way (outside this
unit's scope). Land's lazy read swallows a failed comments read into a refusal, which the existing e2e case for an older-head review relies on.

**Surprising.** CodeRabbit's summary comment carries the same marker with `kind: reviewed` when it posted findings; only the
status line tells a clean review from one with findings, so the line is required.

## Fix pass r1 (review FAIL, one blocking finding)

**Changed.** The marker was trusted from any CodeRabbit comment and from anywhere in it, so a reply or a rate-limited notice that
repeats text others chose could meet (c) alone. Now only CodeRabbit's summary comment is read: its body starts with the generated
line and its leading HTML-comment lines include the summarize line, exactly one such comment, not rate limited or skipped. The
status line comes from the status block and the marker from the risk block, each delimiter once and in order (status, walkthrough,
risk), fenced copies ignored. A marker in any other CodeRabbit comment refuses, a repeated JSON key refuses, and the reason names
the marker count. check-land-e2e.mjs gained a route for the paginated comments read (summary on page 2, a failed read, another bot).

**Evidence.** The new cases were 13 of 114 red first. 16 mutants are caught; one (delimiter-once) survived until a case without a
second marker was added. PR 13 at d5ca0091 passes via the summary; PR 16 (rate limited) refuses.

**Surprising.** The portable check refuses a regex literal ending in three tildes and a slash; the fence pattern is built with
`new RegExp`.
