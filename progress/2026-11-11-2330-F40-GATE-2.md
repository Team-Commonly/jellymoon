# F40, the fixes after gate round 2

- **Done.** The copy's record is written into a file made new (`hook::put`), so nothing at `runs/<id>/copy.new`
  is waited on or written through. A wish that names a run going for another wish stops nothing, two wishes made
  to name each other's runs included. A stop prints a cancelled run as `cancelled` when its record is not
  believed. A look removes a copy on a `not_started` record's word only when the record names no child. A
  `run.lock` that cannot be opened is no lock. F40 has 31 tests at the binary, F39 44.
- **Decided.** `jellymoon run` writes `not_started` with no child named. A record that says `not_started` and
  names a child is a cut-off run: its child is killed, its copy kept and marked failed. One F39 test said the
  opposite and was changed on purpose (`tests/f39/limits.rs`,
  `the_copy_of_a_cut_off_run_whose_record_was_made_to_say_never_started_is_kept_and_its_agent_stopped`). A
  process is signalled when its pid and start mark are the record's, whatever it is (`docs/development/run.md`,
  "A run that was cut off").
- **What follows from the rules, and has no test.** A record changed by hand to name another wish while its run
  goes: `run stop` for the run's own wish is refused too, until the run ends or is cut off. A live run whose
  `run.lock` is closed to the user by hand is taken for cut off by the next look.
- **Open.** Linux and Windows are run by CI only. Windows is linted here without linking:
  `cargo clippy --target x86_64-pc-windows-msvc -p jellymoon -p jellymoon-core -p xtask --all-targets -- -D warnings`.
