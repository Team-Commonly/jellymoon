# F34 · opening the app shows today's page (2026-11-10)

**What changed.** `jellymoon-app` with no `--page` shows a day: the kept page at once, or a waiting page, then the
page core reads (`app/src/today.rs`, no GPUI; the window only swaps the scene). Pages are kept one file a day in
`<JELLYMOON_HOME or ~/.jellymoon>/pages/`. A day is read again when its count of turns differs from the kept page's
`read.turns`, or with `--fresh`. A reading that cannot run is one plain note. `skip.txt` there lists folders left out.

**Evidence.** `cargo test -p jellymoon-app --test f34 --features runtime_shaders`: 6 passed, with the made-up harness
on PATH. `make preflight` green. The real window on a real day was not opened here: no run of the real `claude`.

**What's next.** Join taps to F29's ruling store: `window.rs` `received` gets the day and the clash's two wish ids
(the scene keeps only `clash-<n>`), writes the ruling, and the kept page is read again.

**Surprising.** Cargo gives a test only its own package's binaries, so the app declares the same made-up harness
source again as `f34-claude`; a second `fake-claude` would have collided in `target/debug`.
