# P06R: the shared toolchain cache lands from PR #8

**Changed.** PR #8's two tools commits, cherry-picked onto main without its design base (which landed separately as
NS): `scripts/tools.sh` reads `JM_TOOLCHAIN_CACHE`. Set, Go and Bun live once in the cache and a worktree's `.tools/` is
three symlinks; a cached toolchain is used without taking the lock, and a killed installer's leftovers are recovered.
Archives are deleted after a verified unpack in both modes. Round 2 (owner ruling): the cache root, each entry used,
Go's `bin/` and the linked binaries must be the current user's own, not symlinks, and not group- or other-writable, or
`tools.sh` refuses before it runs anything in them. Unset mode makes its version dirs 0755 again, and Bun's checksum
line is matched exactly. Round 3 (owner ruling, the final fix round): the root is resolved to its physical path and
only that path is checked, installed into and linked to; every directory from `/` down must be the user's or root's
and writable by no one else (a root-owned sticky directory such as `/tmp` only above one of the user's); an ACL that
may grant anything is refused (macOS entries are read, deny-only ones accepted; elsewhere a `+` is refused); a `.` or
`..` component and a symlinked root written with a trailing slash are refused; missing parents are made 0755; a path
`ls` cannot list is named as such. `docs/development/toolchain-cache.md` was rewritten against the code.

**Evidence.** `scripts/check-tools-cache.sh` inside `make preflight`: 29 cases on macOS (24 elsewhere), nothing
downloaded, 15 of them failing against round 2's `tools.sh`. Seven mutants of the round 3 check (no ancestor walk,
"+" read as no ACL, no ACL test, no sticky-directory condition, the configured path instead of the physical one,
parents at the umask, a walk only of a root that already existed) are each caught. Under a clean shell, `./init.sh`
and `make preflight` are green with the cache unset; with it set to a fresh directory, `tools.sh` installed into it,
`make preflight` was green, and a second `tools.sh` reused it with no download.

**Next.** Pin the Go and Bun checksums in the repo, so a cached entry can be re-verified on use; check the rest of a
cached Go tree on use (`go.env`, `pkg/tool/`, `src/`), and until then fix a suspect entry with `chmod -R go-w <dir>`
or delete it; run the cache check on Linux in CI, which today runs no `tools.sh` at all; an atomic dead-lock takeover
and the `kill -0` EPERM case; a one-time cleanup of older worktrees' downloaded archives; a `docs/INDEX.md` row for
the cache doc.

**Surprising.** An installed `.tools/` was 356 MB, not the 460 MB estimated, plus 104 MB of downloaded archives that
were never deleted. Both of round 1's cache checks read the entry they were judging, so a planted entry vouched for
itself. A `+` after the mode is not a reliable sign of an ACL on macOS: `ls` prints `@` instead when the path also has
an extended attribute. And every macOS home directory carries a deny-only ACL, so refusing every ACL would have
refused every cache under a home directory, the place the doc recommends.
