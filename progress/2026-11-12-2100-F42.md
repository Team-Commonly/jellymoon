# F42: a wish typed in the window is kept, and its run starts

- **Done.** The kit has a one-line entry (`crates/sticker-kit/src/entry.rs`, `layout/entry.rs`, `draw/entry.rs`):
  a field, a chip for each option, Enter. The app puts one on a day's page, with a chip for each project of the
  reading (`app/src/wishing.rs`). Enter carries the words and the project's name to core's `wish`; the wish is
  drawn at once; core's `run_apart` starts the checked installed `jellymoon` for it, off the window's thread;
  and once a second the window looks at what core keeps, so the star is drawn with no tap. F42 passes
  (`cargo test -p jellymoon-app --test f42`, 10 tests). Docs: `docs/development/app.md`, "A wish in the window".
- **Core changed by one name.** The cap on a made wish's words is public, `MADE_SAID_MAX` (200): the entry
  takes no more. `made_wishes`, which the F41 handoff expected, was not needed: the app draws a look from
  `made`, as every page does, and reads the reason of a run that was not started from `run_apart`'s answer.
- **Decided: the asking gives a note, not a scene.** The plan's `Later` gave the next scene. `run_apart` can
  wait two minutes for a copy, and the scene on show can change meanwhile (a tap, a reading), so the asking
  gives only what there is to say and the window puts it over the scene on show then (`OnShow::asked`). A look
  is two steps for the same reason: `look` off the thread, `seen` on it, which drops a look made from a scene
  that is no longer on show.
- **Decided: which notes a look keeps.** A look draws the page again and keeps the plain notes the scene on
  show began with that the page does not draw itself. Two notes of the page's own come and go with what is kept
  ("Nothing wished for yet today.", "Your sessions are not told yet.") and are named in `Today::again` so they
  are not carried over. A new note of that kind must be named there too: `tests/f42.rs` holds the two.
- **Decided: the tests' window is a program.** `run_apart` gives the command it starts the caller's
  variables, so a test never calls it in its own process: `app/tests/support/wisher.rs` does what `window.rs`
  does with Enter, started with the test's variables only, and prints each scene to a file (never a pipe: on
  Windows the run inherits it). The app package builds the `jellymoon` command and F39's made-up agent again
  under `f42-` names, since Cargo gives a test only its own package's programs.
- **Not tested: what needs a person at a window.** Typing in the field, an input method's candidate window and
  where it stands, the caret, Tab between chips, Escape, a click elsewhere, `t` while typing, and the look
  redrawing while a wish is being typed. Windows and Linux are CI's: the run tests were run on the Mac only.
- **Open.** A note of a wish is lost when a reading that was going ends and draws its own page. The app cannot
  stop a run (F43). A project past the sixth has no chip.
- **Next: F43.** A stop from the window, through core's `stop_run`, off the window's thread as the asking is.
- **Suggested skills.** `make-pr-easy-to-review`; this PR waits for `GATE: PASS` (Enter in a window starts an
  agent). Then `tdd` for F43.
