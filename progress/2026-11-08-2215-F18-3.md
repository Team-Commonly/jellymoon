# F18 PR 3: the /invite/:token screen

**Changed.** `InviteScreen.tsx` holds the page. Signed out it shows a "Sign in with GitHub to join" link to
`/sign-in?return=<this path>`. Signed in it shows a Join button; Join calls accept once (a ref guards a double click), then goes
to `/pod/:id`. A 410 shows the gone line; any other failure says the server returned an error (status) or could not be reached.
`http.ts` is the injected client (`Http`, `ApiError`, and the browser `fetch` one), `testkit.ts` gets `fakeHttp`.
`App` takes `http` and `signedIn`.

**Evidence.** 7 tests committed red first against a stub (7 failed, 68 passed), then green (75 in the web package). Two mutants
were each caught: auto-join on mount (1 test), the 410 branch dropped (1 test).

**Missing from the API.** No route shows a pod name for an invite code (only `POST /v1/invites/:code/accept` exists), so the
signed-out and signed-in pages cannot name the pod. No route says whether the browser is signed in either; `main.tsx` passes
`signedIn={false}` until the cookie session (F15) lands, so Join is live in tests only. The sign-in route `/sign-in` is the
assumed path and does not exist yet.

**Next.** `invite.spec` (needs the Playwright harness), the sign-in route, a pod-name preview route.
