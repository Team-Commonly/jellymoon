# F48: a run's record names its repo, the commit it started from and the commit it ended as

On branch `f48-record`, one commit on top of `140dc7c` (F44). Gated: it changes what a run writes. Design: ADR 0017,
"Found while building F44". How it is built: `docs/development/run.md` ("What is kept", "What a kill leaves in the
record") and `docs/development/show.md` ("What the record names, and how far it is trusted"). Tests:
`crates/jellymoon/tests/f48.rs` and `tests/f48/` (`shown.rs`, `cut.rs`), 14 tests; the record's two example files
round-trip in a unit test in `run/record.rs`.

## What was built

- `runs/<id>/run.json` gains three names, each left out when it is not known: `repo` (the git folder the repo's
  checkouts share, as the system resolves it), `start` (the commit the copy was made from) and `end` (the commit the
  copy ended as). `repo` and `start` are in the record's first writing, before the harness starts. `end` is written
  in the one writing of the run's end, with `outcome` and `why`, for a run that finished.
- `run show` checks what a record names before git is asked anything: all three or none, each id 40 or 64 hex
  digits, the path from a root. Then the repo is found as F44 finds it and the git folder git names is resolved and
  compared with the record's; the branch's commit, as git printed it, must be the record's `end`; that commit's one
  parent, as git printed it, must be the record's `start`. No word of the record is an argument to git, and nothing
  is looked up at the record's path.
- Two new refusals, in fixed words: `the repo found for run <run> is not the one its record names, so its work is
  not shown` and `the work of run <run> does not start where its record says the run started, so it is not shown as
  the run's`. A branch that names another commit than the record's end takes F44's line, `is not as the run left it`.
- A record from before F48 names none of the three and is shown as F44 built it.

## What each end of a run writes

| A run that | `repo`, `start` | `end` |
|---|---|---|
| was refused before its copy, or at the lock runs are counted behind | no record | |
| was never started | written, then the record goes with the copy | no |
| finished with work | yes | the one commit made of its work |
| finished and changed nothing | yes | the commit its branch was at, which is `start` |
| finished with its copy's folder already gone | yes | no |
| failed, was stopped, ran out of time, could not be committed | yes | no |
| was cut off | yes | no; a look that writes `failed` adds none |

A kill at each step: the table in `run.md`, "What a kill leaves in the record".

## How a path is compared

A run writes the git folder as `fs::canonicalize` gives it. A look canonicalizes the folder git names for the repo
it found and compares the two part by part. The record's path is never canonicalized: that would ask the system
about a place a file chose, which on Windows can be a share on another machine. So a record that spells the same
folder another way is refused. On Windows both sides are the system's final path for the folder (`\\?\C:\...`), so
case, short names and separators are the system's to settle, once on each side.

## Tests, and whether each was red first

Twelve of the fourteen were red at the binary before the code. Not red first:
`a_run_that_was_never_started_leaves_no_record_at_all` and
`shown::a_record_from_before_is_shown_by_the_branchs_tip_and_its_one_parent`, which hold what must not change.
`nothing_else_a_run_writes_changes_and_no_step_of_a_run_in_the_persons_repo_does` was also run against the code
from before with the three names left out of its list, and passed: its list is what a run wrote before F48.
Changed after the code: `shown::the_repo_found_is_compared_as_the_system_resolves_it_and_the_records_path_is_never_resolved`
(the comparison was first made by resolving both paths; see the mutations), and the cases for a folder above and
inside the one named.

F44's tests changed in two places, because a look now goes by the record: `Made::rework` writes the made-up
commit as the record's `end`, and `refused::a_branch_that_is_not_as_the_run_left_it_is_refused` runs on a record
from before, so each case is still refused for its shape.

## Mutations: 22, each against all of F48, all of F44 and core's unit tests

20 killed. The two that live change nothing on a Mac, where git already names the folder as the system resolves
it, so `fs::canonicalize` returns what it was given:

| Mutation | Why it lives |
|---|---|
| the folder found is compared as git spelled it, not resolved | the same path on a Mac; on Windows git prints `C:/...` and it would refuse every run (closed, not open) |
| a run writes the folder as git spelled it, not resolved | the same; the two only differ where git's spelling is not the system's |

Neither can make a look show work it should refuse: both are spellings of the folder git named. They need a
Windows runner to kill.

## Not measured

- Windows and Linux: nothing was run there. Only `cargo clippy --target x86_64-pc-windows-msvc` for core and the
  binary. Whether `fs::canonicalize` gives one path for a folder reached by two drive letters or a `subst` is not known.
- A kill between `commit-tree` and `update-ref`, and between `update-ref` and the copy's removal: reasoned from the
  code's order, not tested. The tests kill while the harness works, and after the copy is gone before the end is written.
- A power loss: the record is renamed into place and not synced. A record that comes back empty is refused as
  `cannot be read`; that was not tested.
- A repo of the SHA-256 format: an id of 64 hex digits passes the check, and no such repo was made.

## Next

- F45 and F46 should refuse a record that names no commits. Whoever can write the home can take the three names
  out of a record and get F44's rule back; that is required of `run show` by F48's second step, and harms nothing
  while a look only shows.
- A run killed after its commit and before its end is written leaves a commit on its branch that no record names.
  `run show` refuses it. Nothing removes that branch.
- ADR 0017 says the three commands "take the work from the record, not from the branch's shape". As built the
  shape is still asked too, and a record from before is shown by shape alone.
