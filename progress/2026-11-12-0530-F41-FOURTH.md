# The rest of PR 144's gate, and tests that leave nothing going

One gated PR, branch `f41-fourth`: it changes what a look takes back. Findings 2 to 8 of the gate review of
`fe8251c` (PR 144), and the reviewer's note on agents a panicking test leaves. Docs: `docs/development/run.md`
("A copy nothing names", the paragraphs on tests' waits) and `copy.md`.

## What changed

- **2 and 3, a record that reaches the copy's git folder from another repo.** `copy/record.rs` `ours` asked
  "inside" of the two paths' names. It now asks it of both as the system resolves them (`fs::canonicalize` on
  each, never one resolved and one not, so Windows's `\\?\` form is on both sides). A record's `own` that
  leaves another repo's git folder by `..`, or goes through a link put inside it, is not inside that repo:
  nothing is done there, and what the home holds of the run goes. The real repo's branch and registration
  stay for the person, as for any record written by hand.
- **4, a plain file at `copies/<run>`** is removed as a link there is (`copy/gone.rs` `unlink`: whatever is at
  the name and is no real folder), and the rest is taken back.
- **5, the wish asked before the count** (`run/cap.rs`, `free`) has a test: a command held after its folder
  was looked up, whose wish gets its run meanwhile, never comes to the claim's two seams.
- **6, the `gitdir` half of `ours`** has a test: the record's repo is the copy's own and the file names
  another place.
- **7, one limit.** `tests/support/mod.rs` `LIMIT`, 90 seconds, for a command a test waits for (was 20) and
  for one it left going (`ended`, was 30). The bounds tests state (60 s, 40 s) are below it and are now what
  fails. Raised, not the bounds lowered: the bounds were measured on a loaded machine, the 20 s was not. A
  command that hangs costs CI 90 seconds a test where it cost 20 or 30.
- **8, the first stop test's comment** says what the test shows (the agent is gone at the first asking) and
  names the `deaf` test that shows the interrupt is first. Its agent ends at either signal, so the test
  cannot show more; the `deaf` test can, and only where an agent can be made deaf.
- **A test that ends leaves nothing going** (`tests/f39/guard.rs`). `World::going` returns a `Going`, which
  kills and waits for its command when dropped. `World` leaves `rec/over` when dropped; every made-up agent,
  and the program one leaves, ends itself at that file (`fake_agent/gate.rs` `minded`), signals or none. The
  world then waits, ten seconds at most, until no agent holds its `rec/live-<pid>` and no `jellymoon run`
  holds a `start.lock` or `run.lock` of its home, and only then is its folder removed.

## Seen red

- Findings 2, 3 and 4: red on the code as it was (the record kept, the other repo's branch deleted, the file
  and everything else left).
- Findings 5 and 6: red with `free()` not called and with the `gitdir` half always true.
- The guard: `panics::a_test_that_panics_leaves_no_agent_and_no_command_going` starts this test program
  again for one test that panics with an agent that never ends, a program that agent left in another process
  group, and a second command held a minute in its claim. Red with `over` never left, and red with `Going`
  not killing.

## Windows, by reading

- `ours`: git prints the repo's and the copy's git folders as `C:/…`; both go through `canonicalize` and are
  compared as `\\?\C:\…` with `starts_with`, by components. Short names are made long on both sides alike.
- The guard opens `live-<pid>`, `start.lock` and `run.lock` to ask for their lock, and closes each at once. It
  does so only as the world is dropped, after the test's last assertion, so no handle of the test's stands in a
  run's folder while a look moves it (the fault of `b0b2137`).
- A dropped `Going` is `TerminateProcess` and a wait; the agent it leaves has no signal to hear and ends at
  `over`. The folder is removed after both are gone, since Windows removes no folder a program stands in.
- The link test (finding 3) prints its skipped line where the account may make no link.

- The raised limit was not seen to be what lets a 60 s bound fail: that mutation takes a minute a test and
