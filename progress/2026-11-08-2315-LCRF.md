# LCRF: the land follow-ups that three reviewed changes left

**Changed.**
- A leftover `refs/heads/land/<n>` is reused only when it is the land commit: the merge tree and exactly main's tip then the PR head as
  parents. The dco check reads the parents, so a commit with the right tree and other parents proves nothing. Anything else is overwritten
  under a lease on that commit. The leftover is read with one call that returns its tree and parents.
- SIGINT, SIGTERM and SIGHUP end land through `process.exit`, which runs exit listeners; the land ref is now deleted from one too (same
  `refs/heads/land/<digits>` guard, once, and the listener is removed when the ref is cleaned).
- The post-merge tree check on the CI path has its own cases: a merged tree that differs from the proven one is recorded `TREE-MISMATCH` on
  the LANDED row with the warning. (The merge has already happened by then, so this records and warns; it cannot refuse.)
- `check-land.mjs` runs its child processes in the repo with `<repo>/.tools/bin` and the system directories as PATH, so a hand run from
  another directory or with another PATH no longer fails the two entropy cases.
- Docs: `workflow.md` states what land checks today (ledger PASS, pod verdict, no failed completed check run; it does not wait for CI), the
  `landing.md` land-ref paragraph states the reuse rule and the signal cleanup, `progress/2026-11-08-LPRE.md` now describes what landed, and the
  LCR3 note points here.

**Skipped, already fine.**
- The harness clock in `check-land-e2e.mjs` is already a function (`now: () => over.now ?? Date.now()`), land never calls it, and the one case that
  depends on elapsed time reads `Date.now()` fresh at the kill and at the end. Nothing reads a time once and reuses it.
- The CodeRabbit gap rule is already restated in `workflow.md` and `landing.md` by the change that introduced it; nothing there still says
  the status-block rule.

**Evidence.** Red first: the leftover-parent cases and the signal cases failed before the code change; the two entropy cases failed from
another directory with a bare PATH before the fix. Mutants (reuse on tree alone, no CI-path tree check, no exit listener) are each caught.
