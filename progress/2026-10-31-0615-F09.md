# F09 fix round 2 (2026-10-31-0615 UTC)

**What changed.** The agent's environment is now exactly the allow-list: agentEnv never returns nil (os/exec gives a nil Env the whole parent environment), and the agent process is built in one place that turns a nil Env into an empty one. The daemon drops the user token on every start path, including a restart with the computer stored. MCP lookup uses own keys only. The stop step checks the held run's own end (`failed`) and its process group; the hold agent ignores SIGTERM. ADR 0001/0005 and the e2e contract table are corrected.

**Evidence.** New TestF09 step (daemon restarted with a user token, none of the seven names set) failed first on JELLYMOON_HOME, JELLYMOON_SERVER, JELLYMOON_HARNESS_FAKE and JELLYMOON_USER_TOKEN, then passed. Unit cases in run_test.go, acp_test.go, cli_test.go and a worker case for four inherited names. Six mutants each fail an assertion. Gate runs are in the report.

**What's next.** F10 onward.

**Surprising.** os/exec adds PWD to any child with a working directory, so "only allow-listed names" needed PWD in the e2e list. The acp guard hides a nil agentEnv from the e2e, so the unit case is what catches that mutant alone.
