# CI: CI runs on pull requests and main; CodeRabbit comments as information only

**Changed.** `.github/workflows/ci.yml` runs on every pull request and every push to `main` (it was dispatch-only), and a
failing check run blocks a land as before. Its e2e job now runs `make e2e-a`, the contract suite against the Worker under
`wrangler dev --local`, as `make preflight` does; before, it ran `make e2e` with no server and every contract test
skipped. `.coderabbit.yaml` turns off CodeRabbit's check run, commit status and approvals, because land vetoes on a failed
check run from any app. AGENTS, CONTRIBUTING, workflow and landing docs say so, and say that the names class of the deny
check runs in CI only once its secret is set.

**Evidence.** `make preflight` green under a clean shell; the pull request's own CI run is green with the suite running.

**Next.** Once the repository is public, a ruleset on `main` requires CI's checks.

**Surprising.** CodeRabbit's `commit_status: false` does nothing on GitHub while `review_progress` is on: it reports a
check run named `CodeRabbit` instead, which land would read. And the e2e job was green while running no contract test.
