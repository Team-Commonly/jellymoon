# F29 · a ruling reaches a running Claude Code session once (2026-11-11)

**What changed.** `jellymoon rule` keeps a ruling as a file in Jellymoon's home; `jellymoon hook` hands each waiting
ruling to the session's main thread, as `additionalContext` on `PostToolUse`; `jellymoon hook install` and
`uninstall` put one piece of text into the harness settings and take exactly it out, replacing the file whole
(new file, sync, rename). `jellymoon uninstall` (F33) removes the hook too. `docs/development/delivery.md` has it all.

**Evidence.** `cargo test -p jellymoon --test f29`: 17 passed, 1 ignored. Core: 32 unit tests, 4 shape tests. The
ignored harness-real step was run by the coordinator on 2026-11-10 and passed, so F29 is `passes: true`.

**What's next.** The app calls `jellymoon_core::rule` from a tapped clash option. No real session on Windows yet.

**Surprising.** Exactly-once needs no lock: a create-new mark file per ruling and session is enough. Claude Code's
exec form (`args`) runs a hook with no shell, which is what makes one entry work on Windows.
