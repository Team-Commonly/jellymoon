# F25 GROUND: an ask whose claims are not grounded is refused

**Governing text (quoted as it stands).**
- `docs/protocol.md:781`: "every GroundedClaim cites at least one toolCalls or messages id, and every id must be a record in this pod (tool calls: on a run of this agent). Otherwise the post is refused with ungrounded."
- `docs/protocol.md:782`: "every number in a GroundedClaim's text must appear in the digest of a tool call it cites, or in the summary or body of a message it cites."
- `docs/protocol.md:92`: `ungrounded` 422, "A claim cites nothing, cites an id that is not a record here, or has a number its evidence lacks."
- `docs/design/protocol.md:17-21`: "Every claim cites stamped evidence ... A post whose claim cites nothing, or whose numbers don't appear in what it cites, is refused with `ungrounded`."
- ADR 0006 "Evidence" (`docs/adr/0006-pod-state-server.md:96-114`): records are "Stamped by the pod, never written by an agent"; "The Worker does not serve evidence."
- ADR 0003 (`:196-202`): "`post` is the PostInput command (F11) ... the core owns what the schema cannot say"; (`:75-76`) "The core keeps only state; it keeps no messages." ADR 0002 says nothing about asks.

**What a number is** (`numbersIn`, unit-tested on each edge in `podcore/test/ground.test.ts`). The rule says a number must
"appear" in the evidence, so both sides are cut into numbers the same way and compared as whole numbers, never as substrings
(`21` does not appear in `212`).
- Digits are any Unicode decimal digit, kept as written (full-width `２１２` matches only `２１２`).
- Decimals and versions: digit groups joined by a single `.` are one number (`4.2`, `1.2.3`). A trailing full stop is not part of it. `4.20` and `4.2` are different numbers; no value arithmetic.
- Thousands separators: a comma is one only in the `1,234` / `12,345,678.9` shape, and is dropped, so `1,024` and `1024` are the same number. Any other comma separates numbers (`1,2` is 1 and 2).
- Percentages and units: `%`, `ms`, `MB` are not part of the number; `87.5%` is 87.5.
- Signs: `-`, `+` or `−` directly before the digits is the number's sign, unless a letter, digit, `_` or `.` comes before it (`2026-11-09` is 2026, 11, 09; `3-5` is 3 and 5). An unsigned claim number appears in a signed one (`3` in `-3`); `-3` needs `-3`; `+3` takes `+3` or `3`, never `-3`.
- Digits inside a word still count (`b98213`, `sha256`): the rule says every number. Spelled-out numbers (`twelve`) are not numbers; that is a known gap.

**Decisions.**
- The core decides; the adapter only looks up. A post with no `evidence` grounds nothing, so an adapter that forgets the lookup fails closed.
- A person has no agent, so a person's ask may cite messages but not tool calls (the rule reads "on a run of this agent").
- The connector write card (ADR 0009) is composed by the pod and cites nothing; its adapter passes `evidence: 'pod'` and the check is skipped for it alone. This needs the lead's ratification (ADR 0009 amended by one line).
- The Worker passes its log's messages and no tool calls: a tool-call cite is `ungrounded` there. `TestF25` is skipped on the Worker; a worker unit test covers both cases.

**Fixtures changed.** The asks of `TestF11`, `TestF12` and `TestF14` cited a made-up `tc_` id. They now cite a person's message ("CI: the
auth fix passed 212 of 212 tests"), posted before the agent runs, which holds the claim's number, so they run on both adapters. The

**Not in this unit.** A message cite lets an agent cite its own earlier post, and a digest holds the call's input, so an agent can
put a number into evidence itself. Both follow the rule as written; closing them is a schema/ADR question. Message lookup scans the
pod's `message.created` events with no index.
