## Two things the coordinator should know

- **Finding 3 is narrower than the ruling's words.** The ruling says "the last line of that file that had one".
  The reader does not decode every line: it decodes a prompt (a line that names an origin) and, only while a turn
  is open, a reply or a user line that is no tool result. Tool results are megabytes each and are never decoded,
  which is why. So the line a folderless line is judged by is the last *decoded* line that had a folder. In a
  run's own session and in a person's own session the two are the same, since every line agrees. They differ only
  in one file that mixes a copy's lines with others: after a typed line in a copy, a reply elsewhere is passed
  over (no turn is open), and a folderless line after it is still left out. `reader.md`, "Not closed", says so.
  Judging by every line would mean decoding every line for its folder; that is a cost to rule on, not to slip in.
- **Finding 1 leaves out whatever a linked `copies` leads to.** A `copies` linked onto a folder the person works
  in leaves every folder below that one out. It is what "as the system resolves it" means, and a run really does
  stand there; `reader.md` says it in one sentence.

What the "last folder" keeps: one `bool` for the file being read, whether the last decoded line with a folder
was in a copy. No folder's text is kept from line to line, so a 64 MiB folder name costs one walk and nothing
after it.
