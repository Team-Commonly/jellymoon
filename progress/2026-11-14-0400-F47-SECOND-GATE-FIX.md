# F47: what its second gate found

On branch `f47-fix2`, one commit on top of `e960aa0`. The account is ADR 0017, "Found while building F47", point 8,
`docs/development/show.md` ("A keep from a page") and `app.md` ("Files the person's tools obey").

## What changed

- **The rule.** A page keeps a file the person's tools obey only when its name was drawn, whole, on the note the
  yes was given under. Core names each in a text of its own and counts none; past six, a page has no yes.
- **A name not printed as it is.** `Waits` has a new part, `plain`: whether every such name is printed as git
  keeps it, byte for byte. Work with one that is not (a name that looks like a credential, printed `[redacted]`)
  has no yes on a page, in the same sentence as work past six. The sentence no longer speaks of `--ask`.
- **The kit** places a text note's options only under a body drawn whole, and plans such a note with that room.
- **The names bind.** The tap carries them, and the keep checks them as a set under its lock.

## What the next session should know: open rows

1. A file name that reads like a count (`a, and 5 more`) is drawn as its own text, and still reads so.
2. A zero-width joiner in a printed name is not seen by the person.
3. Names that do not fit the window leave the note with no choice and no sentence that says why.
4. On the command line `run keep --ask` names 200 such files at most and prints a name that looks like a
   credential as `[redacted]`, so `--with-settings` is a yes to those. A page says nothing of `--ask` now; the
   command was not changed here.
5. One mutation lives: in `keep.rs`, `landed`, the keep told that no check is of the work's own files
   (`std::mem::take(&mut works) && false`), so a carried name that is no file of the work is let by. Only the
   unit test on `judge` fails for the rule. A page cannot reach it: `work_tapped` refuses, before the keep,
   any carried names that are not the ones the work's note would say now, so through a page the names given to
   `keep_named` are always the work's. A test would need a work that changes between that check and the keep's
   lock, and no test holds a keep there yet.
6. The rows of `2026-11-14-0215-F47-GATE-FIX.md` are still open.
