# F55's gate findings: the window starts when the words can be seen

**What changed.** On branch `f55-fix`, one commit on `658aa7f`. F55 itself landed on main as PR 172 (`658aa7f`), not
as the "one commit on `596007c`" its handoff names. A heard wish's four seconds, a refusal's six and the ear's five
are counted from the first tick at or after their event (`hear.rs`, `Since`), never from the tick before it.
`hear --run` says how a run ended when it ended at once; the input's last line with no line break is held to
65 535 bytes; `voice.toml` refuses a key held with Shift alone, and names back no value that holds an unseen character.

**The evidence.** `cargo test -p jellymoon --test f55` and `--test f30`, the fixture `hear-events.jsonl` and the smoke
step `hear`, each with the tick that starts the window. `docs/development/hear.md`; ADR 0019, "Found while building
F55", 14 to 16.

**What's next.** F58 sends a tick right after it forwards the ear's final words: it starts the four seconds and
prints nothing. F56 draws the ring from `left` as before.

**Surprising.** A hold's length is still measured between the ticks before its two key events, which carry no time
of their own: F58 should tick with each key event, or F60 give the events a time. Whether `run_apart` answers that
a run goes or that it ended is a race (`run/apart.rs`) for a harness that began, so the test of a run that ended
at once plays an agent whose stream does not start as a run's: it never began, and the answer waits for its end.
