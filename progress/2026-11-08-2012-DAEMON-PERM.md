# DAEMON-PERM: the daemon answers permission requests by policy and cancels a session before it signals

**Changed.** `session/request_permission` is answered with the request's reject option (`reject_once`, else `reject_always`, else
the `cancelled` outcome); an agent added with `jellymoon agent add ... --allow-permissions` gets `allow_once` instead, never
`allow_always`. Each request and answer is logged by tool call id and kind, never title or input. Other agent requests still get
-32601. A run that is stopped (`run.stop`, which the daemon now handles), reaches its deadline (the claim's `expiresAt`) or
loses its daemon gets `session/cancel`, a 2 s wait for the turn to end, then the existing SIGTERM and SIGKILL. A stop ends the
run `cancelled`; the deadline and a daemon stop end it `failed`. ADR 0007 records it; ADR 0005's open items point to it. The fake
agent gained `permission=<kinds>`, `cancel` and `deaf`.

**Evidence.** Red first, each committed before its fix: the permission and cancel tests in `daemon/internal/acp` (5 failing), then
the `run.stop`, deadline and allow-setting tests in `daemon/internal/daemon` (4 failing). Four mutants (deny answers allow,
cancel never sent, wait skipped, allow setting ignored) are each caught. `make preflight` green twice (`E2E_MS=13354` and
`21076`, `STEPS=64/64`), `make e2e-a` `STEPS=67/67`, `go test ./daemon/... -count=3 -race` green. Entropy: daemon 2462 / 3000,
e2e 4577 / 4650 (73 left).

**Next.** Relaying a permission request to the pod as an ask a person rules on (F12) is the open item in ADR 0007. The cancel
wait is a fixed 2 s.

**Surprising.** The daemon did not handle `run.stop` at all, so cancel-on-stop needed the frame handled and a per-run context
first. A cancel-mode agent that answers at once cannot tell a client that waits from one that does not; it needs a delay.
