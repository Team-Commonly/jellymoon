# The run follow-up: what the gate of F48 and the review of F44 left open

Branch `run-follow-up`, on `main` at `7293533`. One change, 18 items: 1 to 8 from the gate of PR 159 (F48),
9 to 18 from the after-merge review of PR 158 (F44). No feature row changes. It changes what a run writes in the
repo, so it waits for `GATE: PASS`.

## What changed

**A run's end (`copy/clean.rs`).**
- The commit is put on the run's name with `update-ref --no-deref` and the old value. A run's name made
  symbolic between the read and the write no longer moves the branch it leads to.
- A run that changed nothing asks git the same step once more, with its commit as old and new value, and has
  failed as "could not be committed" when the branch is not there any more.
- `copy clean` reads the branch as a run does. A branch that is gone or symbolic is refused in core's own words.

**A record (`run/record.rs`, `run/end.rs`, `run/show.rs`).**
- `Record::named` is the one place the three names are read. A finished run's words and names must agree:
  `one commit` with `end != start`, `changed nothing` with `end == start`.
- A cut-off run that a look wrote down is one Jellymoon wrote. `run show` says "was cut off" before and after.

**A look (`copy/work.rs`, `call.rs`, `still.rs`, `run/show.rs`).**
- Every read has a bound: the answer about the branch (16 KiB) and what git says on stderr, too. A commit read
  to its limit is refused.
- `cut` is true whenever the text printed is less than the file. A text with no whole word in what was read is
  refused. `--file <n>` reads the bytes of file `n` only.
- No git, or a home folder git cannot be started in, has its own line.
- `--no-renames` is gone: plumbing finds no rename unless told, and `f44/shapes.rs` proves it against a config.

**Tests.** `f39/made.rs` holds what F44's and F48's tests shared. The made-up git can now return after its
`first` step (`returns`), so a test can change the repo between two of a run's git steps and let the run go on:
`f48/raced.rs`. The record's writing is waited for by a file, not a clock (`busy::step`).

**`init.sh`.** The scoreboard says `blocked` only while something a feature's `blockedBy` names does not pass.

## What was not done as written, and why

- The review's item on the home's faults asked for a doc sentence in the coordinator's list and for a line of
  its own in the ruling. The ruling won: both are there.
- The bound on stderr holds for a look's reads (`call::run_most`). A run's own git steps still read stderr
  whole: closing that pipe would end an `add -A` that warns at length.
- Five more names in the obeyed list, and a test of a name hidden by the cut, were already on `main` (`05c350a`).

## What is not closed

- Windows and Linux were not run for this change: only a Mac. CI is the first run of the new tests there.
- No clean baseline was taken before the first edit: `./init.sh` waited for the build lock and then ran on a
  tree already being edited. The whole of `make preflight` was run once, at the end.
- Most of the new tests were written with the code, not before it. What shows each can fail is 26 single
  mutations of the changed code, run one at a time against core's tests and `--test f44 --test f48`: all 26
  failed a test, 25 at the binary and one (the bound on stderr) in core.
- A branch moved by hand after a run's last check, or ever after, is not where the record's `end` says.
  `run keep` and `run toss` must compare it again (ADR 0017, "What `run keep` and `run toss` may build on").
- A failed run's words say its copy is kept when the folder may be gone. The second form comes with `run toss`.
- The F48 handoff (`2026-11-13-1400-F48-RECORD.md`) has head lines that are stale after this change. They were
  left alone on purpose: a handoff says what was true when it was written.
