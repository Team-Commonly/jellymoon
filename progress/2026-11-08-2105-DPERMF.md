# DPERMF: close the review gaps in the permission and cancel change

**Changed.** After a stop, any ending of the session (`stopReason` cancelled, a JSON-RPC error on `session/prompt`, or the agent
exiting without answering) now ends the run with the cause that cancelled it, so a stop reads `cancelled` in all three; a
deadline or daemon stop still reads `failed`. An option with a missing, non-string or empty `optionId` is never selected, and
when none is usable the answer is the `cancelled` outcome. ADR 0007 has a dated line for each. Tests added for the three
mutants the review found surviving (a permission request after `session/cancel`, the answer carrying the option's kind where its
`optionId` belongs, the answer's JSON-RPC id) and for a SIGTERM-ignoring agent, so removing the SIGKILL step is caught in
`daemon/internal/acp`, not only in e2e. The unit-tier fake agent gained `stubborn`, `exit-on-cancel` and `error-on-cancel`.

**Evidence.** Red first, committed before the fixes: seven failing lines (four for the stop cause, three for option ids). The
permission cases call `serve` directly with ids that differ from kinds, so no agent mode was needed for them. Mutants, each
reverted and confirmed with `git diff --quiet`: permission-after-cancel, optionId-as-kind, wrong response id, SIGKILL removed,
optionId check removed and the stop-cause fix reverted are each caught. Entropy: daemon 2996 of 3000; the new helper modes and
tests were written to fit (the first draft was 3056 and failed the gate).

**Next.** The stop-then-exit case is pinned in `acp`; the daemon-level outcome follows from it (`errStopped` ends the run
`cancelled`) and has no test of its own with an agent that exits on cancel. Adding one needs a fake-agent mode and about 15
lines of daemon budget, which this change does not have.

**Surprising.** The entropy cap counts raw lines in test files, comments included, so a helper's size is its cost.
