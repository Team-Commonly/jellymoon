# The findings of PR 141's gate, the cap among one wish's commands, and tests that do not need an idle machine

One gated PR, branch `f41-third`: it changes what an agent may do on the machine (when a run is refused, what a
look removes, which folder a run copies). Docs: `docs/development/run.md` ("The order" 3, "A copy nothing
names", "Three runs at once", the paragraph on tests' waits) and `copy.md`.

## What changed

- **Four commands for one wish (item 7).** Each took its run's lock and only then asked the wish, so three of
  them standing there counted as three runs and the fourth was told the cap. Possible since F41 made the cap
  (PR 138); PR 141 did not change the order. Now the wish is asked, the run's lock taken, the record written
  and the wish named, all behind `runs/going.lock` (`run/cap.rs` `claim`, `run.rs` `start` and `name`).
  `tests/f41/cap.rs` holds three with the lock taken and the wish not named while a fourth arrives.
- **1, another spelling.** `run/place.rs` `resolved`: the reviewer's fix. Only a last name that is itself a
  link has its target's name compared with the project. A link to a folder of another name, another case
  included, is still refused.
- **2, the start lock asked again** once the copies' lock is had (`copy.rs` `undo`, `copy/hold.rs` `let_go`).
- **3, a record that names another repo.** A check, not a sentence: `copy/record.rs` `ours`. The repo is acted
  on only when the copy's git folder is inside it and its `gitdir` file names `copies/<run>/.git`.
- **4, a link at `copies/<run>`** is removed as itself (`copy/gone.rs` `unlink`), then the rest as usual.
- **5.** `tidy` runs before `place::folder`. What is left of the window is in run.md, "What is not closed".
- **6, three mutations that survived** now have tests: the link led elsewhere after the lookup (`named.rs`), a
  run whose own lock is held (`left.rs`), and the look's guard, as a unit test in `run/never.rs`: `bury` returns
  before `unstarted` for a wish not at work, so no command reaches that guard with a `done` wish.

## Tests and the clock (item 0)

Seams, all read only by a build with debug assertions: `busy::pause` (ends early at the file
`JELLYMOON_TEST_GO` names, leaves `<that file>.at` on arrival) at the claim, the naming, the lookup, the
look's wait and the note's wait; `busy::test_file` for a limit counted from a file
(`JELLYMOON_TEST_RUN_LIMIT_FROM`, `JELLYMOON_TEST_GIT_LIMIT_FROM`); `JELLYMOON_TEST_DOOR_WAIT_MS`.

Changed: F41 `found_world` (asker's wait 60 s) and `silent_world` (0.1 s) for the seven tests whose agent says
nothing; `left::a_copy_whose_command_still_lives…` (held by a file, was 2.5 s); F38 `limits` (the git limit
counted from `stalled`); F39 `limits::to_its_limit` (limit counted from `started`), two "did not wait" bounds
10 s to 60 s, `refused::a_harness_too_old_while_the_day_is_locked…` (the lock held until the command ended, was
5 s), `freed` 5 s to 30 s; F40 `closed` and two of `late` (held by a file), `deaf` and the first stop test
(grace 15 s to 60 s, bound 10 s to 40 s; the 4 s upper bound removed, `heard` says the same), `nothing`
(the run's wait 15 s to 60 s).

Left as they are, each an upper bound on one command's time that a very slow machine can break:
`f39/safe.rs` "the page waited" under 3 s (a kill, where a stop would take 5); `f40/deaf.rs` lower bounds only;
`f40/late.rs` first test, where the run's end must be written within the second a look waits; the sleeps of
`f39/stream.rs` and `f39/refused.rs` that only hold a lock "for a while". The app's F42 tests wait on no clock.
