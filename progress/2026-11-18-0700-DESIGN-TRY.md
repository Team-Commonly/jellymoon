# DESIGN-TRY: a run's work tried with a command the person named (ADR 0024, F88 to F90)

**What changed.** On branch `design-try`, on `6c238e9` (the designs for midnight and the result). A design only: no
Rust. ADR 0024 decides how a person learns whether a run's work works: they name one try command for a project
(`jellymoon project try <name> --with ...`), kept on the project's line of the list; core splits it by rules of its
own, with no shell, and runs it in the run's copy after the work is committed and before the wish is told; how it
ended is kept in the run's record and printed as `tried`; a note of its own says it in Jellymoon's words, and
`Keep it` after a failed try asks once more. `feature_list.json` gains F88 to F90, all `passes: false`. The
glossary gains try command and try.

**The evidence.** `cargo xtask check`, clean. Every "today" was read in the code; nothing was built, run or
measured, and no test was run, on macOS, Linux or Windows.

**What's next.** F88 (name, see and remove the command), then F89 (core tries and prints, after F88 and F85), then
F90 (the window's note, after F89 and F86). After them: an OS sandbox around the try, and a follow-up's run that is
handed a failed try's last lines as data.

**Surprising.**
- The commit and the removal of a copy are one step behind one lock (`copy/clean.rs`, `end_copy`). A try has to
  sit between them, or what it writes (`target/`, a cache) is committed as work. So `end_copy` is cut in two.
- A copy holds only what git tracks, so every try starts cold: no `target/`, no `node_modules`.
- The harness's list of variables and a short `PATH` mean a `cargo` under the home's own folder may not be found.
- The list refuses a field it does not know, so an older build finds a list with a try command unusable.
- A line of the list written by hand can now name a program to start. Until now no file of Jellymoon's could.
- The note that asks before a keep reads its texts as file names, so the ask after a failed try is a second note.
- The repo names no sandbox anywhere. The try runs a model's code as the person, and the ADR says so plainly.

**Open.** Whether 600 seconds suit a cold build, how many real commands pass the rule of words, what a try leaves
going on Windows, and whether a try typed from a terminal can still open it.
