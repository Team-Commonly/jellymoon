# F26 fixes from the fresh-context review

**Changed** (rules in `docs/development/reader.md`).
- Reader: only a regular `.jsonl` file in a real folder is opened; a link or a pipe is not. A typed line whose `uuid` was already read is dropped with its replies. A prompt nobody typed (a peer's message, another program's prompt) ends the reply window; a task notice still does not. `--skip` names are trimmed, and a line with no `cwd` is matched by its session's folder name. A line over 64 MiB is read past.
- `redact.Credentials`: a run with a `/` and no `+` or `=` is judged one segment at a time, so long paths survive. New shapes: Google `AIza`, `glpat-`, `hf_`, `sk_live_`, `rk_live_`, and the password in a URL.
- Caps: daemon 8780 to 8890, e2e 10820 to 10850 (`docs/entropy/caps/2026-11-10-daemon-e2e-reader-review-fixes.md`).

**Evidence.** TestF26 was red first: the reader hung on a pipe named `x.jsonl` until the test's 20 s limit. After the change, each reader fix was turned off by hand in turn (eight variants) and TestF26 failed each time. The redact cases and the line cap (`reader_test.go`, with the cap set to 2000 bytes) were red before the code.

**Decisions.**
- Paths: `/` stays in the long-run alphabet, because taking it out stops catching base64 that holds one. Instead a run with a slash and no `+` or `=` is split, and only a segment of 40 or more mixed characters is replaced. A base64 run with slashes, no `+` or `=`, and no 40-character segment now passes.
- To end a reply window at a prompt with no `origin`, the reader now decodes `user` lines while a turn is open, except any line holding `"tool_result"` as a JSON value. Those are the megabyte lines; the quoted word cannot occur inside a JSON string.
- Meta lines and compaction summaries do not end a reply window: the harness writes them mid-turn.
- A line with no `cwd` keeps an empty `project`; only the skip match uses the folder name.

**Not proved.** Read time on a real day after the wider decode was not measured.
