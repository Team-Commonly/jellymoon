# F51: a run's session is kept, its last word is data, and a run can ask

On branch `f51-asks`, one commit on top of F46's final commit `110bc10`. It changes what an agent may do on the machine (a run's
command line) and adds the first text of an agent's that a run prints, so a fresh gate reads it before it merges.
The whole account is `docs/development/run.md`, "A run that asks"; ADR 0018 has what was decided while it was
built ("Found while building F51") and what the coordinator measured.

## What was built

- **The command line.** `--no-session-persistence` is gone; `--session-id <id>` and `--json-schema <schema>` are
  in. The id is core's, a random UUID made before the harness starts, and is in the record's first writing.
- **The start.** The init line must list the five tools and `StructuredOutput`, each once, and name the session it
  was given. Another session is its own failure, and the child is stopped at once.
- **The last word.** `run/asks.rs` reads the first result's `structured_output` in two shapes only. `done` is a
  finished run as before; `asks` with a question that passes the door is a run that asks; anything else fails.
- **A run that asks.** Record: outcome `asks`, the fixed line, `question`. Wish: `needs_you` with `question`.
  The copy is neither committed nor marked failed; the run's lock is let go. `jellymoon run` prints seven names.
- **After it.** A look writes nothing; `run stop`, `run show`, `run keep` and a second `run` refuse in fixed
  words; `run toss` tosses it as a run that did not finish, with the run's lock held.
- **The reader.** A spelling of `copies` with no name is no spelling; `reader.md` says an empty working directory
  is none; three tests at the binary for a run's kept session and a line with no folder.
- **The smoke chain** has an `asks` step after `toss`.

## What the next unit should know

1. **F52 takes `runs/<id>/run.lock`** before it reads the record of a run that asks, as a toss does
   (`asks::for_toss`). A toss that holds it counts as a run going.
2. **A copy that asks is never pruned.** Until F52, only a toss removes it.
3. **The record's `session` is believed only in the shape `asks::fresh` makes.** F53's fork id can be core's too
   (ADR 0018, "Measured").
4. **Nothing here was run on a real harness.** The fixed words that ask for `done` or `asks`, an old harness's
   words for `--json-schema` and `--session-id`, and what a real harness does with a last word that does not fit
   are not measured.
5. **The old-harness line names the option.** `never::old(option)`; three options are looked for.

## The seven findings F46's gate left, closed here

1. **A name of the person's that points at the run's branch** (a symbolic ref) is asked for by a toss and by a
   keep with the question a take-back asks (`copy/back.rs`, `pointed_at`). The branch is left, in fixed words; a
   toss writes its record and lets the wish go, and a keep's `why` ends with the words.
2. **The head of a toss that found the record saying tossed** claims no cause: "the record of run <id> said it
   was tossed, and this toss did what was left to do". `toss.md` says beside rule 2 that a later toss deletes a
   branch put back by hand.
3. and 4. **`toss.md`** has the line on a packed branch with a loose other spelling, and the line that another
   spelling stood on is refused on every disk.
5. **A record that says tossed and holds `kept` or `onto`** is not one Jellymoon wrote.
6. **A rebase's `head-name` and a `BISECT_START`** under another spelling have their test (`tests/f46/landed.rs`).
7. **Budgets**, as `entropy.toml` holds them. The rows in `2026-11-13-2100-F46-TOSS.md` are stale.
