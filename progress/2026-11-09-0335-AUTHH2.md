# AUTHH2: the sign-in hardening follow-ups (the review's N1-N7 on PR 45)

**Changed.** ADR 0008, "Hardening" items 1, 2, 6 and a new 7. Server: an https `PUBLIC_URL` outside ENV=local without
`TRUST_PROXY` refuses to start, naming it; `TRUST_PROXY=<n>` is a hop count (the n-th `X-Forwarded-For` entry from the
right, 0 for the socket's address); `hub.sockets` drops a hash with its last socket. Both adapters: a user token with a null
expiry is expired (computer and run tokens keep null as never), chosen over a backfill. Worker: `worker/migrations`
(`0000_initial.sql`, the schema before the hardening, and `0001_auth_hardening.sql`), `migrations_dir` in both configs;
the `token_pods` row is written before the upgrade reaches the pod and dropped if the pod does not open it; logout closes
sockets with `Promise.allSettled` and always clears the cookie. TestAUTHH's start-limit step sends a different
`X-Forwarded-For` and `X-Real-IP` on every request.

**Evidence.** Red: the new worker tests failed 3 of 4 (null expiry, logout with a failing pod, the token_pods order; the
limiter-key test is a mutant judge and passed), the migrations test could not load (no `worker/migrations`), the server test
could not load (no `forwardedFor`). `make e2e-a-migrated` with only 0000 present: STEPS=5/19. Green: e2e-c and e2e-a
26/26 for TestF15, TestBSESS and TestAUTHH; `make e2e-a-migrated` 26/26; `bun test server worker` 123/123. Mutants, all
caught: the limiter on `X-Forwarded-For` (server by TestAUTHH; worker by the unit test and TestAUTHH), the TRUST_PROXY
check removed, null expiry as never (both adapters), `hub.sockets` not pruned, logout with `Promise.all`, and (extra) no
token_pods row before the pod.

**Next.** Still open (ADR 0008, "Not in this unit"): the `/device` page (F18), a token refresh, an open socket outliving its
token's expiry, `token_pods` rows of expired tokens, `jmc_` tokens that never expire. A real D1 still needs a hosting
decision (ADR 0006).

**Surprising.** The migration needed a 0000: without a baseline, a D1 made from today's `schema.sql` already has
`expires_at`, and 0001's `alter table` would fail on it. With 0000 as the old schema, every real D1 comes from migrations
alone, and a unit test holds `schema.sql` equal to them.

**Fix round 1 (review of PR 49).** A logout racing a socket's open left it open on a revoked token, on both adapters. The
Worker now authenticates again after the pod answers 101 and closes, drops the row and refuses; the server reads the token
again in `onOpen` after registering the socket. An http `PUBLIC_URL` outside ENV=local is refused, and its scheme is the
parsed one. The migration shape test compares indexes and foreign keys. Left on the Worker: two concurrent dials of one
token in one pod (ADR 0008, Hardening 6).
