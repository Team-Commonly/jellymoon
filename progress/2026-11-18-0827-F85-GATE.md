# F85, after its gate: a text passes the door whole, and a quoted line is held to the cleaned file

**What changed.** On branch `f85-fix`, on `a60aaf3` (F85 on main `3f3bd31`). One commit. The gate of `a60aaf3`
failed with two blockers, each a way a credential's shape could be printed by `run show` and `run waiting`.

- **A text goes to the door as the run wrote it** (`run/told.rs`, `clean`). It was joined into one line first,
  so the door never saw a line break and never read a credential a break splits as one. Now the door is given
  the text with its breaks, as a run's question is, and prints such a credential as `[redacted]`. The check for
  a character that draws as nothing stays on the joined text.
- **A quoted line is held to its side of the file cleaned whole** (`change`). A line was cleaned alone, and a
  body line of a private key block is no credential's shape by itself when it is short. Now each side that is
  quoted from is cleaned once, as `--file <n>` cleans a file, and every quoted line must also be a whole line of
  it. A key block is the mark there from its first line to its last, so no line of one is quoted, from a file
  the work made, changed or removed.
- **Two rows the gate found missing** (`tests/f85/held.rs`): a file the work turned into a link with a `before`
  quote, and a file that held a zero byte before the work and is text after it. Both held before; nothing tried
  them.
- **Docs**: `show.md` (how a text passes the door; the cleaned side of a quoted line), `run.md` (core takes a
  `result` from any harness, and only the schema keeps a real one from sending it until F87).

**The evidence.** Red first on `a60aaf3`, with the tests only: the split key printed as
`use AIza kLmNo… here` for `did`, where `use [redacted] here` was expected, and the first body line of a key block
wrapped at 39 characters was printed as an `after` line of a made file. The two rows of the link and the zero
byte were never red. Green now: fmt, `xtask check`, clippy on core and the binary, core's tests, and
`cargo test -p jellymoon --test f85` with 19 tests.

| Mutation | Killed by |
|---|---|
| A text goes to the door joined, its breaks read as spaces first | `f85/checks.rs`, the texts' test, and core's unit test |
| The unseen check is asked of the text as written, not joined | the same two, and `f85/kept.rs` |
| An `after` line is not held to the cleaned side | `f85/held.rs`, the key block's test |
| A `before` line is not held to the cleaned side | the same |
| The kind of the file is not asked | `f85/held.rs`, the link's row |
| A zero byte is text | `f85/held.rs`, the zero byte's row |

The last two are the ones that survived in the first entry. That entry called them one rule held twice, which is
true only of the after side of a plain file; each now has a row that kills it alone.

**Budgets, joined.** `entropy.toml` at this commit: core 16916 and the binary 28519. F85 raised core from 16383
to 16898 and the binary from 27695 to 28438 on main `3f3bd31`; this commit raises them by 18 and by 81, all of
the 81 tests. The figures in `2026-11-18-0752-F85.md` were counted on the design's commit and are that entry's.

**Open.**

- The whole of the binary's tests and the smoke chain were not run for this commit, only `f85` and core.
- Linux and Windows were not run here. The link is written into git's index, so no test makes a link in a folder.
- A file that holds a private key's first line and no last line is the mark from there to its end, so no line
  after it is quoted. That is how `--file <n>` prints it.
- What a text may still carry (combining marks, look-alike letters, a literal `[redacted]`, counts written in
  words) is F86's to hold on the ground it draws these texts on.
