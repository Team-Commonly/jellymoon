# F75: the door a test starts `jellymoon-app` through, and the door's review

**What changed.** Built on branch `f75-door` on main `ae740f7`, then joined to main `5d4711a` on
branch `f75-join` as one commit (see "Joined to main"). Tests, their support and xtask; nothing that ships.

- **One rule, two doors.** The rule is `crates/jellymoon/tests/support/door/world.rs`: what a door refuses of a
  world (`refusal`, `refusal_as`, `no_root`) and the command it makes for one it has passed (`command`). The
  binary's door (`crates/jellymoon/tests/support/door.rs`) and the app's (`app/tests/support/door.rs`) each take
  that file as a module with `#[path]`, and add only the programs they start and their temporary folders. Tests
  of two crates share no module any other way, and a crate for it was not allowed; `env!("CARGO_BIN_EXE_…")`
  compiles only in the crate that builds the program, so the names stay with each door. About ten lines of
  wrapper are written twice.
- **The app's door** starts `jellymoon-app` (`door::app`), the made-up `jellymoon` (`door::jellymoon`), the two
  made-up windows (`door::window`) and any other program (`door::command`: git, the bundle script, a made-up
  harness). `support::scratch` and `support::system_scratch` make every temporary folder. A world with no home
  still starts (`door::BARE`).
- **Moved through it.** 37 places were mapped under `app/tests` (28 at `ae740f7`, 9 more at the join), none under `app/src` (no test there starts a
  program, builds a home or names the look). Twelve starts: `jellymoon-app` five times (`support/mod.rs`,
  `support/day.rs`, `f49.rs`, `f28/words.rs`, `f56/jelly.rs`), the made-up `jellymoon` and the tapping window
  (`support/worked.rs`), the wishing window (`support/wished.rs`), git twice, the bundle script (`bundle.rs`),
  and `mkfifo` (`f49.rs`), which is the system's and names no world, and stays. Twelve temporary folders, nine
  of them outside the support, now from `support::scratch`. Four tests that had the harness looked for in the
  process's own environment (`f35.rs`, `f37.rs`, `f43.rs`, `f47/gone.rs`) name the world's made-up harness.
- **`/tmp` is no temporary folder of the app's door.** No app test needs a home of another owner. The binary's
  door keeps it on Unix, in its own `roots()`.
- **The rule in xtask** (`rules/door.rs`, tests in `rules/door_tests.rs`) is one rule with a table of two doors.
  For the app: a test file outside `support/door.rs` that names a program of the door, a test file outside
  `support/` that makes a temporary folder, and a test anywhere in the app that has the harness looked for with
  the process's own environment.

A fault found on the way, in finding 5's test: a path written with a separator at its end was not read as a link
(`read_link` fails on it), so two links in a row were taken for a folder. `resolved` takes the path part by part
first; the f74 test holds a link to a link out, written both ways.

**Sentences a person can read, added or changed.**
- `REFUSED`: "a test starts nothing in a world outside the temporary folders: the home, Jellymoon's folder,
  JELLYMOON_APP_DIR, JELLYMOON_BIN_DIR, CLAUDE_CONFIG_DIR, the login shell, --logs, --settings and --repo are
  each under the system's temporary folder (in the binary's tests /tmp on Unix too) or the one Cargo gives tests,
  and no --logs or CLAUDE_CONFIG_DIR climbs out of the folder it is read from", then "; this one named" and the
  name.
- `NO_ROOT`: "a test starts nothing: a temporary folder is a file system's root, or it is or holds the home of
  the person running the tests".
- `cargo xtask check`: "a test names a built program outside `support/door.rs`; start it through
  `support::door`" (was: outside the test support). The two others are as they were.

**Open.**
- Windows and Linux were not run. The code was read once as Windows compiles it: `not_ours` names its Unix
  imports in full, `SystemRoot` is passed on, and what Windows reads differently is a value of `refusal_as`,
  tested here. The climbing test's Windows half runs on any system; the root and home test restarts the test
  program with `TMPDIR`, `TMP` and `TEMP`, and was seen only with `TMPDIR`.
- The rule reads lines: a program started under a name it builds from parts, or an argument added to a command
  after the door made it, is not seen (`workflow.md`).
- One of xtask's tests that this change does not touch, `a_home_is_named_for_its_process_and_its_start_and_no_two_runs_share_a_name`
  (`smoke/build.rs`), failed in two of the rounds here and passed in the others: it asks for two names in a row
  and they were the same to the nanosecond. It is on main as it is; the final round ran xtask's tests until that
  one passed and says how many times it took.
- Three other builders are in the app. Their tests were touched only on the lines that start a program or make
  a folder; a start they add outside the door is refused by `cargo xtask check` once this lands.
