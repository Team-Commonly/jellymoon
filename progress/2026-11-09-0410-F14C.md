# F14C: close F14, with the real sign-in

**Changed.**
- `e2e/f14_test.go`: the `TODO(F15)` sign-in is gone. `TestF14` now signs both people in the way F15 built: the browser leg
  through the server's own start and callback (the stub's authorize hop is played in the test with that person's identity, as
  `TestBSESS` does, so the parallel `TestF15` steering the shared stub cannot touch it), then a device code approved with the
  session cookie, then the `jmu_` token the device flow exchanges for it. The test route `/__test/session` is no longer used by
  this walk. The new helper is `f14.signsIn`.
- `entropy.json` and `docs/entropy/caps/2026-11-09-e2e-7830-to-7880.md`: the e2e cap grows by 50 for the helper (measured 7,873).
- `feature_list.json`: F14 `"passes": true`. No product code changed.

**Where CI runs it.** `TestF14` has no skip. `e2e-local` runs `make e2e-c` (the server on Postgres), `e2e-worker` runs `make e2e-a`
(the Worker under `wrangler dev --local`; its skip list is `TestF19` only), and `e2e-deployed` runs the same suite against the
release bundle. `TestF14Budget` waits for it in each. Each of those jobs runs the whole contract suite, `TestF14` included.

**Evidence.** All on a clean tree, PGlite for the server (no Docker, so the Postgres service container was not run here).
- `make e2e-c`: `TestF14` PASS 2.36 s, `TestF14Budget` PASS, `E2E_MS=19654 STEPS=116/116`.
- `make e2e-a`: `TestF14` PASS 3.11 s, `TestF14Budget` PASS, `E2E_MS=20020 STEPS=112/112`.
- `TestF14` alone, server: `E2E_MS=1711 STEPS=10/10`; Worker: `E2E_MS=1931 STEPS=10/10` (`go test ./e2e -run TestF14`, with `JM_E2E_SERVER` set).
The F14 walk itself is 10 steps and about 2 s, against a 60 s bound.

**Next.** The two gaps the first F14 note found stay open and are product calls: the `decision_ruled` wake does not name the task,
and `jm_task_update` refuses a note. The test still writes the task id into the second script by hand.

**Surprising.** The device flow's 2 s poll interval costs nothing here: the first poll after approval is not rate limited, so
the walk needs no sleep between approve and token. The new sign-in also moved the walk from the test route to the same
code path a person uses, so a break in F15 now fails F14 too.
