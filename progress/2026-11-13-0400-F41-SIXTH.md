# The findings of PR 148's gate: which repo a look acts in, and which branch is someone's

On branch `f41-fifth`, on top of `6fe1ae9`. Gated: it changes what a look removes in a repo. Docs:
`docs/development/run.md` ("A copy nothing names") and `copy.md`. Tests: `crates/jellymoon/tests/f41/shapes.rs`
(new) and `asked.rs`.

## What changed

- **Blocking 1 and 2, the repo a record names.** `record::asked` asked whether the copy's git folder was
  inside the repo's. It now asks `kept_by`: the resolved git folder is directly in `<repo>/worktrees`, and the
  folder named as the repo holds no `commondir` file, which every worktree's git folder holds and a repo's own
  does not. So a record that names the copy's own git folder, another worktree's, or a repo whose git folder
  encloses the copy's repo (a submodule's outer repo) reads as "answers and does not list": nothing is done in
  it. A repo that is itself a linked worktree, and a repo with its git folder inside another's, are still
  taken back whole.
- **Blocking 3, a checkout with no commit.** `HEAD` is in the `rev-list` only when
  `rev-parse --verify --quiet HEAD^{commit}` finds a commit.
- **Blocking 4, a branch someone stands on.** `back::theirs` (was `unbranch`) keeps the branch when `HEAD` is
  that branch in the repo's own checkout or in any worktree but the copy (`symbolic-ref` through each folder
  of `worktrees`, `Repo::through`), when another ref is a symbolic ref to it (`for-each-ref
  --format=%(symref)`), or when it holds a commit of its own as before. This check also keeps the branch in
  blocking 1's shape by itself, so that shape is held twice.
- **5**: `copy.md` says a failed git step leaves the record and not the copy's folder.
- **6, the line.** The look that gives a copy up after thirty days says one line on stderr of `jellymoon
  page`, exit 0. stderr was chosen because a page has a `why` only on a wish, and a run no wish names has no
  place on it. Core hands the line back beside the page (`with_made_said`; `with_made` and `made` are as they
  were, for the app). The app and `jellymoon run` do not say it. A time in the future in `put_off` is taken as
  now and written so.
- **8**: tests for the four surviving mutations (table below). The order in `add`'s failure path is held by a
  new wait, `JELLYMOON_TEST_UNMADE_WAIT_MS`, between its two git steps.
- **9, deslop**: `forget` is the one body of `remove_ours` and the thirty-day arm; `add` builds the `Record`
  once and `note` writes it again; `unasked` is `put_off`, since it also holds a failed git step and a folder
  that could not be removed. No example JSON of a copy's record exists, so none changed. A record written by
  the build of `6fe1ae9` with `unasked` reads as one with no time, and gets a new thirty days.
- **7**: `run.md` lists another folder at the repo's path as not closed.

## Not closed

- New: another folder at the repo's path (record and copy go at once). A damaged git folder in `worktrees`
  makes the question fail, and the branch stays thirty days. The line is not said by the app or by `run`.
  A detached checkout at the branch's commit, with no commit of its own, does not keep the branch.
- Carried: a branch in a repo that answers and does not list (`git worktree prune` between looks); a command
  killed inside git between the branch and the git folder; an orphan git child writing the copy's folder; an
  unreadable record; `copies` removed or a link, kept thirty days; Windows drives that do not resolve; thirty
  days tested by editing the record; the cut-off test uses a stalled git; Windows only linted; the worlds of
  F27, F29, F37 and F38 have no guard.
- Windows, read and not run: `kept_by` compares two paths both from `canonicalize`, so both carry the same
  `\\?\` form; the link-to-a-file shape uses `symlink_file` and is skipped where it cannot be made.
