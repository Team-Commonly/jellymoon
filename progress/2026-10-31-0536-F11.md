# F11 progress (2026-10-31-0536 UTC)

**What changed.** A new core command `post` stores the whole PostInput: it refuses a missing or blank summary (summary_required), an ask without needs, options or context and a non-ask carrying them, duplicate option ids, a recommendation naming no option, and any pod-set field. It stamps the receipt (run record, the harness the adapter holds, wake reason, call count) and opens an ask's decision. `tool_call` counts MCP calls: the MCP adapter tells the pod after each tools/call on a run token. The fake agent can run a scripted list of MCP calls. Decisions: ADR 0003, GLOSSARY (receipt).

**Evidence.** `go test ./e2e -run TestF11` passes all 5 steps in about 3 s. Six mutants (121-character limit, ask without options accepted, client receipt accepted over MCP, call count from a header, harness from a header, decision created expired) each fail an assertion. podcore/test/post.test.ts and worker/test/mcp.test.ts cover the core and the count.

**What's next.** F12 rules on a decision. Grounding (`ungrounded`) is not enforced: the pod has no tool-call records to cite yet, so the test's ask cites ids the pod has never seen, as the fixtures do.

**Surprising.** The contract does not say whether the posting call counts toward toolCalls. A tool call record has an end time, so the receipt counts calls already answered: refused ones included, the post itself not.
