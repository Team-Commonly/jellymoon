# The smoke chain runs the programs cargo says it built

One PR, branch `smoke-paths`, off main. Finding 8 of the review of #147, which was not blocking: the chain looked
for its programs in `debug` under the target folder, so a `build.target` in a cargo config (which puts them in a
folder named for the triple) made it run what an earlier build had left, and no test tied the chain to cargo's
answer (mutation X5 survived).

## What changed

- `smoke/build.rs`: the build is started with `--message-format=json-render-diagnostics`. `built` gives every
  program by its name at the `executable` path of cargo's message; no `build-finished` message with `success` is
  no programs. What the compiler says is still drawn for a person, on stderr.
- `smoke.rs`: `World` holds those paths where it held a folder. `world` builds and makes a run's world, and ends
  the run when a program the chain runs (`jellymoon`, `jellymoon-app`, `fake-claude`, `fake-agent`) was not named.
- `docs/development/smoke.md`: the "not held" sentence is gone, and the paragraph says how the programs are found.

Lines: 143 added and 31 removed in four files without this one; Rust is 132 and 26. Nothing was deleted but
`World`'s folder of programs and the "not held" sentence. xtask's budget is raised by 106 with its reason.

## Proof

`the_chain_runs_the_programs_cargo_says_it_built_and_not_what_lies_in_the_debug_folder` builds a made-up package
whose own config sets `build.target` to the host's triple, with a stale file of the program's name in `debug`, and
runs the program through the chain's own `World`. It takes about two seconds.

Mutations, one at a time: X5 (the chain looks in `debug` again), a needed program not missed, a build that did
not finish well still having programs, a build script taken for a program, and the build not asked for its
messages are each caught. The build's exit code not being looked at survived, so that check was removed: cargo
says `build-finished` with `success` itself.
