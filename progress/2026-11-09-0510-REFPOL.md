# REFPOL: Referrer-Policy on both adapters

**Changed.**
- `server/src/app.ts`: a middleware sets `Referrer-Policy: no-referrer` on every reply (not on a 101 upgrade). This covers the web client's HTML, which `web.ts` serves.
- `worker/src/front.ts`: `handle` wraps the old router and sets the same header on every reply. The Worker serves no HTML itself, so the header goes on its API replies, the same shape as the server.
- Caps: worker 2,390 -> 2,420, server 4,070 -> 4,080, with one note in `docs/entropy/caps/`.

**Evidence.** `server/test/web.test.ts` and `worker/test/referrer.test.ts` check `/device?code=...`, `/invite/<token>`, an error and `/healthz`. Both were red (`null` for the header) before the change and green after. The e2e contract suite has no place that reads response headers, so it got no assertion.
