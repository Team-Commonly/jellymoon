# F11 fix pass (2026-11-08-1258 UTC)

**What changed.** A receipt's `taskId` now comes from the run record: `run_claim` keeps the task that woke the run, and a post can no longer write it. Every stored post is read back and compared field by field. A forged identity header and every public path to the pod's call count are tried from outside. The MCP adapter counts a call before it dispatches it and refuses a call that cannot be counted; the post riding on that call is marked by a header the Worker alone sets, so the receipt still leaves it out. The dead run branch of `message_post` is gone. Decisions: ADR 0003 and the e2e cap note in ADR 0001.

**Evidence.** Each fix has its red test committed first. Mutants (receipt task from the post, non-asks stored as fyi/done, incoming identity header kept, a public count route, count after dispatch, a failed count ignored, the mark header kept from the caller) each fail an assertion.

**What's next.** CodeRabbit and CI on this head. Grounding is still not enforced.

**Surprising.** Counting before dispatch put the posting call into its own receipt, against the ruling that it counts calls answered before the post. The first fix flipped the contract; the second kept the ruling by marking the carrying post.
