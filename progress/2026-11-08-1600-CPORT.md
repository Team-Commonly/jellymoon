# CPORT: the pod-state server (Bun, Hono, Postgres) is the server on main

**Changed.** `server/` is the adapter `make e2e` and CI's `e2e-local` run. It passes the whole contract suite except three
tests that need the Worker's object-only routes (`discard`, `instance`, `stored-alarm`, `woke`); each skip has its reason in
`docs/development/e2e-contract.md`. Ported from the Worker: schema validation with refusals, hashed invite codes, random ids
and wake seeds, presence (a computer socket marks its agents online, a restart sets them offline), the evict test route, and
the bearer-gated test-route mode. Production Postgres is `DATABASE_URL` through `Bun.SQL`; PGlite is local only. `make e2e-a`
keeps the Worker run, and CI has an `e2e-worker` job beside `e2e-local`. ADR 0005 records the decision; ADR 0001 has the cap.

**Evidence.** First full `make e2e-c` in a clean shell: `E2E_MS=31345 STEPS=42/42`, 3 skips. `podcore/`, `schema/` and `gen/`
are untouched.

**Next.** Sharding across processes and hosting are open (ADR 0005). `init.sh` runs `make e2e` after `make preflight`, which
already ran it, so the suite runs twice there; `init.sh` is outside this unit.

**Surprising.** jsonb reorders object keys, and creation order is the order of the state's keys, so pod state is stored as text.
