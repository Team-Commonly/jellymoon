# F41: a wish made with `--run` starts its own run

- **Done.** `jellymoon wish --run [--logs] [--skip]` keeps the wish and starts `jellymoon run` for it through
  core's `run_apart` (`crates/jellymoon-core/src/run/apart.rs`): a process of its own, in a group of its own,
  which goes on after the asker has exited. `jellymoon run` takes `--logs` and `--skip` too. The rows F41, F42
  and F43 are in `feature_list.json`; F41 passes (`cargo test -p jellymoon --test f41`, 14 tests, and the smoke
  step `wish-run`). Docs: `docs/development/run.md`, "A run started apart" and "Three runs at once"; `wish.md`.
- **Decided: what is read of the command (ruling 6).** Its stdin and stdout are null and its stderr is a pipe
  read only until the wish names the run or the command ends. After that nobody reads it, and it still exits 0
  for a completed run: `tests/f41/apart.rs` reads its exit code through the made-up asker
  (`tests/support/fake_asker.rs`), which stands between core and the real command.
- **Decided: the cap is exact (ruling 4).** A run takes its own lock behind `runs/going.lock`, where the held
  locks are counted first (`run/cap.rs`). Six `jellymoon run` at once, each made to wait 200 ms between its
  count and its claim, give exactly three runs. A count before the copy, with no lock, only spares the copy.
- **Decided: the plan's sketch changed in four places.** With no harness nothing is spawned: `run_apart` asks
  for the harness first, so `why` is core's own line. The reason of a command that ended is its first stderr
  line through `redact::line`, not its stdout. `going.rs` is `cap.rs`, since `run.rs` has a function `going`.
  `Started.why` is the wish's own `why` once the wish names a run.
- **Decided: a folder of one's own (ruling 3).** On Unix a folder found in a log must have the owner of the
  person's home folder; a home that cannot be read makes every found folder refused. `--repo` is not asked.
- **Not tested.** Windows beyond the lint (process group, closed pipe, the end of the command). An asker whose
  terminal is closed (`SIGHUP`): the command has a group of its own, not a session. Linux is CI's.
- **Open, from before.** The orphan copy when `jellymoon run` is killed between writing the wish back and taking
  its copy back (`progress/2026-11-12-0900-F40-FOLLOW.md`).
