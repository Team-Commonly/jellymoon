## What was built

1. **The made folder is told from another only by a mark that holds both the system's number and a time of
   making (the blocker).** `made_still` asked for a number alone. Where the system says no time of making the
   number decided by itself, and such a file system may hand a removed folder's number to the next one made.
   It now asks for both; without either, a making whose file is gone ends as moved, exit 1, as on Windows.
   - *A mark's time, by reading `mark`.* It is `created().ok()`: none exactly when the system's answer is an
     error. That is what Linux gives for a file system or a kernel that reports no time of making. It was not
     checked here, in Rust's source or on a disk, what a Mac or a BSD gives for a volume that keeps none: from
     memory they always answer with some time, so a mark there may hold a time that is not one.
   - *Who else compares marks with `==`.* `ours`, beside the making's file, which is the rule there on every
     system; and `take_back`, for `projects` (finding 4). Nothing else.
2. **`MOVED` says "so this command listed nothing".** The test's copy in `f65/alone.rs` and the row in
   `project.md` follow.
3. **The unit test of `made_still` holds every pair**: both, the number alone, the time alone, neither, on
   each side, sixteen in all; only whole and whole, equal, is taken.
4. **`take_back` asks `made_still` for `projects` too**, through `Made::made_projects`, which takes the mark
   now there as a value so a test can hold it on every system.
   - *What follows.* `projects` holds no file of a making, so the mark is all that tells it. On Windows, and
     where no time of making is kept, a making that fails after it made `projects` now leaves it, empty.
     Before, Windows removed it by its time alone. `f65/half.rs` held the home to three names after a failed
     first making on every system; it now holds `projects` too where the system's word does not tell.
