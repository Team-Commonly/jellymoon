# DESIGN-RESULT: a run's work told as a result (ADR 0023, F85 to F87)

**What changed.** On branch `design-result`, on main `303ece4`. A design only: no Rust. ADR 0023 decides how a
person understands a run's work without reading a file: the run ends with a result in its last word, a short list
of pieces from a closed catalogue (`did`, `change`, `decided`, `unsure`), core checks each against the work at
every look and drops what fails, and the kit draws the run's words as quoted words in a note over the unchanged
note with `Keep it` and `Toss it`. `feature_list.json` gains F85 to F87, all `passes: false`. The glossary gains
result and piece (of a result). The number 0022 and the ids F83 and F84 are left for a design in flight.

**The evidence.** `cargo xtask check`, clean. Every "today" was read in the code; nothing was built, run or
measured, and no test was run.

**What's next.** F85 (core reads, keeps, checks and prints a result), then F86 (the note) and F87 (the run is
asked for it), each after F85. After them: a run that asks carries its question's context the same way.

**Surprising.**
- A run cannot run anything: five tools, none a shell, and its prompt says so. Core keeps no tool line either.
  So nothing can be drawn as "checked", and the note says in Jellymoon's words that nothing was run.
- Today a last word with any part beside `state` fails the run, so a result has to be let in without ever
  failing one.
- Only `change` can be proved against the work. The three prose kinds are the run's say-so, held to the door and
  to the quoted ground.
- The kit's one `quoted` is cut with `…`, not counted, so the kit needs one new note.
- The door a question passes turns `"` into `'`, so a quoted line of code is cleaned as a file's text is.
- At 960x640 the work's note takes the column; the result is then its first rows and a count.

**Open.** Whether Claude Code holds a nested schema under `--json-schema`, and how often a model quotes a line to
the character: F87 measures both on real runs.
