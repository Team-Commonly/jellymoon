# F65: the made folder is known by a file of the making's own, and the second gate's notes

On branch `f65-new`, on its head `9391068` (main joined in up to F57, #181). One commit.

## The fault

CI on Windows failed core's `what_is_taken_back_is_the_folder_that_was_made_and_never_one_the_list_names`: a
folder removed and made again under the same name was taken back. On Windows the mark was the time of making
alone, and Windows hands a folder made again under a name within a few seconds the time of the one before. So a
folder a hand put in place during a making was removed with what it held.

## What changed

- **The made folder holds a file of its making** (`.jellymoon-making-<process>-<clock>-<count>`), written before
  anything else is in it. `Made::ours` asks for the mark and the file, before the folder is listed and before it
  is taken back. The file is removed once the line is on the list, and from a made folder the list names. It is
  the same code on every system: no `cfg(windows)`, no `unsafe`, no new dependency, nothing unstable.
- **Why not a folder held open.** It would stop a hand's remove on Windows for the length of a making, but by
  code no machine here runs, with tests only Windows can prove, and the handle goes before the take-back, so the
  window between the look and the act stays. The file is proved on the Mac and on Linux as it is on Windows.
- **Note 1.** Jellymoon's folder, made to hold the lock, is removed when a refusal leaves it empty.
- **Notes 3 and 4.** At the binary: a hand writes the line for the folder being made (the project is made); the
  list cannot be written (the folder is taken back, or stays when the list names it). In core: `kept_as` passes
  on what the look at the folder said, and only another name is the file system's sentence.
- **Note 5.** A refusal after the folder was made ends `; the folder made for it meanwhile was taken back` when
  its own words do not say so. The other sentence says "removed or replaced".
- **Note 6.** `named` in `wish.rs` refuses U+034F, U+115F, U+1160, U+3164, U+FFA0, U+2800 and U+FE00 to U+FE0F,
  for `project add` and `project new`.
- **Notes 2 and 8.** `project.md` and ADR 0020 say "the format, the branch or who may read it"; the ADR says CI
  runs `project new` on Linux and Windows; the first progress file says where the branch stands; the closure
  in `take_back` is `on_the_list`.
- `new.rs`'s unit tests moved to `project/new/tests.rs`.

## Windows, which was not run here

- The failing test now passes there because the folder put in place holds no file, whatever its time of making.
- `a_folder_that_looks_like_the_made_one_from_outside…` gives the folder put in place the very mark of the made
  one, which is what Windows did, and fails on every system when the file is not asked for (mutation W1).
- At the binary, `a_folder_put_in_place…` is the test Windows alone proves: on Unix the system's number kills
  the swap without the file.
- That Windows keeps the old time of making is from CI's failure and the documented tunnelling of a name; no
  line here depends on it.

## Left open

- The look and the act are two steps; no lock stops a hand between them, on any system.
- A hand that copies the making's file into its own folder passes on Windows.
- A killed making leaves the file in the folder, with the repo.
- Jellymoon's folder stays when `runs/no-hooks` was made in it, when the lock could not be taken, and a folder
  above it that was made for it stays.
- M17 (the kept name never compared at the binary) is as it was.
- **The check of a name is every project's, not only `add`'s and `new`'s.** A folder typed in whose last name
  holds one of the new characters (an emoji written with U+FE0F, say) is no longer offered and a wish for it is
  refused as no project's name; and a list with a line of such a name, added before, is not used at all until
  the line is taken out by hand.
