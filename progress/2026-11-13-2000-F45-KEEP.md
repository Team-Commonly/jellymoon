# F45: `jellymoon run keep`

On branch `f45-keep`, one commit on top of `6db8e48`. It is the first command that writes to a person's branch
and working tree, so a fresh gate reads it before it merges. The whole account is `docs/development/keep.md`;
ADR 0017 has what was measured and what was found ("Measured", "Found while building F45").

## What was built

`jellymoon run keep --wish <id> [--ask] [--with-settings]`. Core's part is `copy/keep.rs` (the checks and the five
steps), `copy/keep/fits.rs` (whether what would land fits the checkout), `copy/keep/made.rs` (the merged tree and
the one new commit) and `run/keep.rs` (the record and every printed word). The binary parses three words and
prints.

- The one step that writes the checkout is `git merge --ff-only`, with every word that takes away what a repo's
  config could add. What it is given is always a commit ahead of the branch, so git does it whole or not at all.
- With commits of the person's own, the tree is merged in the store (`merge-tree --write-tree`) and one commit is
  made by `commit-tree` under the name git's config gives. Nothing names it until it lands.
- The record takes `kept` and `onto` before the checkout is touched, and `work: kept` after. The next keep asks
  the refs whether the record's commit is in the record's branch.
- A home-wide lock (`runs/keep.lock`) is held from before the record is read.

## What the coordinator should know

1. **git writes the person's ref, not core.** The rule given was that every ref write names the whole ref with
   `--no-deref` and an old value. The run's branch is deleted that way. The person's branch is moved by
   `merge --ff-only` itself: a ref write apart from the checkout would leave one ahead of the other at a cut.
   `keep.md`, "What is not closed", says what that leaves open.
2. **Two names more are printed than the row lists**: `settings` and, with `--ask`, `fits`. With `--ask` a reason
   the work does not fit is data, exit 0.
3. **Stricter than the row**: removing another repo's entry or `.gitmodules` is refused too; a file with a
   `filter` attribute is refused; a made file whose place on the disk is taken is refused before git is asked.
4. **Work the branch holds already** is marked kept and nothing is landed.
5. **A `HEAD` that names a name for a branch** lands on the branch git follows it to. `symbolic-ref` with
   `--no-recurse` would refuse it, and is newer than the oldest git a forward keep works with.
6. **`fake_git.rs` grew two modes**: with a file `says` it answers `version`, and under any name but git's it is a
   planted program that leaves `ran-<name>` beside itself.

## Mutations

47 changes were made to the five core files, one at a time, each run against core's unit tests and `--test f45`.
44 were caught. Five were alive on the first pass and three of them have a test now: work the person moved
forward to and went on from (the commit printed is the run's), a run's branch a checkout came to stand on after a
cut keep (it is left), and a checkout git had written whole before the cut (the next keep finishes it).

Three are alive, and each is a second guard behind a first that the tests do reach:

| Change | Why nothing fails |
|---|---|
| `--no-overwrite-ignore` taken out of the merge | git's trial (`read-tree -n -m -u`) and the look at the disk both refuse an ignored file first |
| `--no-autostash` taken out of the merge | an unsaved change where the work goes is refused first; one elsewhere would be stashed and put back the same |
| a folder below the top of the checkout let through | from below, git names the shared folder by a relative path, and opening it fails in the same words |

## Not run, not closed

- Nothing was run on Windows or Linux. No test uses `sh`; the planted hooks, filter, driver and signer are the
  built `fake-git` under another name. The driver and the filter are named to git by their path, which git hands
  to a shell: on Windows that case may need the path quoted, and was not run.
- git 2.38 and 2.39 were not run: a made-up git says it is older, and the refusal is tested.
- A kill inside git's own checkout, real LFS, a sparse checkout and a partial clone: `keep.md`, "What is not closed".
- `jellymoon run keep` was run only in scratch repos of the tests and the smoke chain.
