# The five findings of PR 146's gate: a look asks the repo first, and leaves no branch it cannot take back

One gated PR, branch `f41-fifth`: it changes what a look takes back. Docs: `docs/development/run.md` ("A copy
nothing names") and `copy.md`. The rule the coordinator set for findings 1 and 2: no branch or registration of
Jellymoon's own that no look ever takes back.

## What changed

- **The take-back is `copy/back.rs`** (moved out of `copy.rs`, which was at 393 lines with it).
- **The repo is asked first** (`copy/record.rs` `asked`, was `ours`): three answers. `Ours`: the repo lists
  the copy. `Not`: the repo's git folder resolves and the copy's git folder or `gitdir` file is not there, is
  outside the repo, or names another place. `Unasked`: the repo's git folder does not resolve, or something on
  the way cannot be read for another reason than not being there.
- **Finding 2, a repo that could not be asked.** Nothing is done: the copy and its record stay for the next
  look. Before, the home's files went at that look and the branch and registration stayed for good.
- **The bound is thirty days** (`PUT_OFF`). The first look that could not take a left copy back puts the time
  in the copy's record (`unasked`, left out of the file when none). A look more than thirty days after it
  removes the copy's folder and `runs/<id>` and does nothing in a repo. Time was chosen, and not "the repo's
  folder is gone", because a look cannot tell a removed repo from a moved one or from a volume not mounted:
  the moved-and-back test and the gone-for-good test look the same at one look. The same bound covers a git
  step that fails at every look.
- **Finding 1, a look cut off between its git steps.** No proof was found that a branch is Jellymoon's once
  the repo's registration of the copy is gone: all that is left is the record and the home, and whoever can
  write the record can write the rest of the home. So the branch is not finished on the record's word. The
  order was changed instead: the branch goes first and the registration last, in every take-back (a look's,
  the command's own, and a copy that could not be made). A look cut off before the registration went is
  finished by the next, since the repo still lists the copy; one cut off after has no branch left.
- **`--glob=refs/*`, not `--all`**, in the `rev-list` that asks whether the branch has a commit of its own.
  With the registration still there, `--all` counts the copy's own `HEAD`, which is the branch: every branch
  then looks reached, and one with a commit of its own was removed (seen red).
- **A git step that fails keeps the record.** Before, a `rev-list` that failed or was stopped kept the branch
  and went on to remove the record, so the branch stayed for good. Whether the branch is there is now asked
  first (`rev-parse --verify --quiet`), and a `rev-list` that fails ends the look's take-back with the record
  kept.
- **Found while testing, and fixed: a command killed while its copy was made.** `run.md` listed it as not
  closed. git makes the folder, the branch and the registration in one call, and the record was written
  after. The record is now written before git is called, naming `worktrees/<run>` in the shared git folder,
  and again with what git says. The test helper `held_in_the_claim` had this race in it: it took the copy's
  folder for the claim, and a second call in one world could kill the command before its record was written.
  It now waits for the file the command leaves at the place (`claimed.at`).
- **Finding 3**: `copies` a link to a folder that holds a plain file of the run's name; the file stays.
- **Finding 4**: a record that names its own repo through a link is taken back whole.
- **Finding 5**: in `tests/f39/panics.rs` the first command is handed to `take()` and held two seconds before
  it writes its end, so only the world's wait covers it; the outer test asks the runs' start locks itself and
  not only through `alive`.

## Seen red

- On the code as it was: the cut-off look (branch left after the `remove` step), the repo moved, the repo

- The command killed while its copy was made: red with the first record not written.

## The reviewer's note on Windows

Read, not run. `fs::canonicalize` on Windows opens the folder and asks the system for its final path, which
some RAM disks and mapped drives do not answer. Before this change every left copy of a repo there was "not
ours": its record went at the first look and the branch stayed. Now it is `Unasked`: the record is kept, for
thirty days, and then the home's files go. The record is no longer lost at once, and the copy is still never
taken back whole there. Not closed.

Other Windows points read: the mode-000 test is skipped there with a printed line; the two link tests are
skipped where the account may make no link; the repo is renamed and removed with no process standing in it
(the command is killed and waited for first); in `panics.rs` the handed-over command may hold the inner test's
output open for its two seconds, which only makes the outer test wait.

## Not closed

- A branch of the run's name in a repo that answers and does not list the copy is never removed. A look no
  longer leaves that state; `git worktree prune` or git's own `gc` between two looks can.
- git makes the branch and the copy's git folder in one call: a command killed between the two, inside git,
  leaves the branch.
- A git child of a killed command goes on writing the copy's folder; the next `copy clean` removes it.
- A copy's record that cannot be read is never taken back and never removed.
- `copies` itself removed or made a link: kept thirty days, then only the home's files go.
- Thirty days is not tested by waiting: the test sets the record's time by hand.
- Windows is only linted here.
