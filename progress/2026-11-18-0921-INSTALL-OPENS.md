# The installer opens the app (install opens)

On branch `install-opens`, one commit on `0de6160`. The owner ran the one-line installer and wrote "I ran it but
still didn't see it": it ended by printing an `open` command and never opened the app.

## What was built

1. **`install.sh` opens the installed `Jellymoon.app`** with `open "<app folder>/Jellymoon.app"`, by the path it
   put it at, after the checksum passed and everything is in place. It first says, in one line, "Opening Jellymoon
   now: it shows today's page, read with one call through your own Claude Code." `JELLYMOON_NO_OPEN` set to
   anything not empty skips it. If `open` fails or is not there the install stands, the exit is 0, and the closing
   lines say "Could not open it from here; the install itself is done." and the `open` command to run by hand.
2. **The closing lines** no longer tell the person to run `open` when it was opened. The rest is as it was: where
   things went, the `PATH` line, the open-folder line, the program run from a terminal, `jellymoon uninstall`.
3. **An update** opens the app the same way. `open` on a running app brings it to the front and starts no second
   copy; the running program keeps the code it had loaded, as it did when the bundle was moved under it before.
   So the installer adds one line on an update, "If it was already open, it stays the version you had until you
   quit it and open it again.", and never looks for the app, quits it or restarts it.
4. **`docs/development/install.md` and the README** say the app opens, name `JELLYMOON_NO_OPEN`, and say how to
   install a release candidate: `JELLYMOON_RELEASE_URL=.../releases/download/<tag>` set for `sh`, not for `curl`.

## How the tests keep the real `open` away

Every world that runs the installer sets `JELLYMOON_NO_OPEN=1` (`Mac::command`, for any world that names a
release) or has a made-up `open` first on `PATH` (`Mac::install_opening`). The door holds it as its rule: a world
that names `JELLYMOON_RELEASE_URL` or an argument `install.sh`, with neither, panics with one fixed sentence
(`unguarded_installer`, `door/world.rs`). The non-Mac test of the refusal on other systems starts `sh` itself and
is refused by the installer before it reaches any `open`.

## What was red first

Against the installer of `origin/main`: the opened-once test, the update test and the failing-`open` test failed.
The "never opened" test and the door's test passed at once: an installer that never opens cannot fail the first,
and the door's rule was already there; the mutations are what hold them.

## Mutations

| Mutation | Killed by |
|---|---|
| Opened before the download and checksum | the never-opened test, and the three others (the log is not what it should be) |
| Opened when `JELLYMOON_NO_OPEN` is set | the never-opened test |
| A failing `open` fails the install | the failing-`open` test |
| `open` is given the apps folder, not the app | the opened-once, update and failing-`open` tests |

## What is open

Nothing in a test starts the real `open`, so the real one on a real Mac has not been run by this change. Windows
and Linux are not run; the new tests are Mac-only except the door's.
