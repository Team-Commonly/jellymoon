# F40: a run can be stopped (`f40`)

- **Done.** `jellymoon run stop --wish <id>` leaves an empty request, `runs/<id>/stop`; the `jellymoon run` that
  owns the child finds it, sends the child's group `SIGINT`, then `SIGTERM`, then `SIGKILL`, five seconds after
  each asking, and writes the one end: `cancelled`, a fourth outcome. The wish needs the person, has no star and
  has had its run; the copy is kept as a failed run's is. Both commands print the same line.
- **Denials.** Still counted from the first result line, now also on a cancelled run. Nothing adds to a run's
  list and no new check was invented: `run.md`, "What is denied", says what the measured stream can show.
- **Evidence.** 17 tests in `tests/f40.rs` and `tests/f40/`: agents deaf to the interrupt, to the signal and to
  both; two stops at once; a stop against the run's own finish, eight rounds, one end each; a request left by
  hand; a locked day; nothing going. With the interrupt left out, the three deaf tests fail. Smoke has a `stop`
  step. F39's test folder moved to `tests/f39/world.rs`, which F40 uses too; F39's 37 tests pass unchanged.
- **Decided.** A stop found while the child goes is `cancelled` even after a result that said success. A run
  that was cut off is written down as cut off by `run stop`, not as cancelled.
- **Surprise.** The file's name sorts after `1700-F39-GATE`; it was written earlier in the day than that says.
- **Next.** Open: Linux and Windows were built blind (Windows ends the child at once, nothing else); whether
  Claude Code ends cleanly at `SIGINT` was never measured; a stop asked while the copy is being made is refused
  as no run; a stuck `jellymoon run` is not ended over its head. The app neither starts nor stops a run.
