# F43, after the gate: the eight findings on PR 143

- **Done.** The two blocking and six other findings of the gate on PR 143 are fixed in one commit on `f43`, each
  with a test seen red under its own mutation (21 mutations, one at a time, all killed). Docs:
  `docs/development/app.md` ("A wish in the window", "A tap that stops a run"), `crates/sticker-kit/README.md`.
- **1. A project switched off by a name above its folder.** A chip, and a wish from the window, now need a
  folder of that name typed in that day that the reader does not switch off: `jellymoon_core::wishable` and
  `wish_offered` ask `reader::typed_in`, the reader part of the lookup a run finds its repo by. Held by
  `f42/notes.rs` (two tests), `f42/run.rs` and core's unit test.
- **Decided: the reader's part only.** The chip rule does not ask whether the folder is on disk, is a repo, or is
  the only one of its name (`run/place.rs`): those stay the run's to say, in its note. So a project of a kept
  page with no folder typed in today has no chip, and a wish for it is made with `jellymoon wish`.
- **What it costs.** Every session log of the day is read once more when the window opens, when a reading ends,
  and for each Enter, always off the window's thread. Measured as one `jellymoon day`, release build, on 300
  made-up logs (137 MB, 10,000 turns on the day): 0.9 s, 2.4 s cold. A small day is a few milliseconds. On a
  large logs folder an Enter therefore waits about a second, with the entry pale. If that is too long, the
  answer is to keep the day's folders from the reading, which is a new feature.
- **2. Refused words.** Enter no longer empties the entry. It waits with its words, pale and with no caret, and
  takes no key, click, second Enter or composition until `Page::answer_entry(kept)`. Deleted: `put_back`,
  `put_back_entry` and their tests, and the `back` words in `OnShow::answered`.
- **3. The name, not the place.** `EntryMade.option` is the chip's name; core is asked for that name and
  refuses one it no longer offers.
- **4. N3, N6, N7, N8, N11** each have an assertion in `app/tests/f43/notes.rs`. N11 uses a kept wish that
  names a run of which nothing is kept, not a killed process, so it runs on every system.
- **5. Core on the window's thread.** `OnShow::entry` is gone. The first entry (`OnShow::offering`) and each
  reading's (`Today::offered`) are work for another thread; the window opens with no entry.
- **6. A note names its wish** by `jellymoon_core::wish_start`, core's cleaning, and a kept wish by what core
  kept. **7.** A tap on a choice to stop that is not on show is `Chosen::Nothing`. **8.** A stop's note
  replaces the notes of the stops before.
- **`window.rs::open`** was 61 lines from its signature to its brace and passed: the limit is clippy's
  (`clippy.toml`), which does not count comments or blank lines, not `cargo xtask check`'s. It is 35 lines now.
- **Tests whose expectations changed.** Enter keeps the words until answered (`tests/entry.rs`,
  `tests/entry_draw.rs`, `f42.rs`); options are names (`wish(.., "kitchen")`, `enters("alpha", ..)`); the
  refusal for no chosen project is "No project was chosen, so nothing was sent."; a note's start is cut by
  core, so 39 characters and the mark, not 40; the test of the names reaching the run now makes its wish as a
  terminal does (`wisher`'s `ask`), since the window keeps no wish for that folder.
- **Windows.** A chip needs a full path, so `support/day.rs::work` writes `C:\work\<name>` there. Not run on
  Windows or Linux here: CI's.
- **Open.** The in-process chip tests read the logs in the machine's own time zone (`TimeZone::system`); the
  made-up day is typed at 16:00 to 18:00 UTC, so they would fail on a machine at UTC+6 or later. CI is UTC.
- **Not tested: what needs a person at a window.** The pale words and the missing caret while the entry waits,
  keys dropped meanwhile, an input method that is refused a composition then, the entry appearing a moment
  after the window, Tab and a click on a chip, and the taps on a character and on "Stop it".
- **Suggested skills.** `make-pr-easy-to-review`; the PR still waits for `GATE: PASS`.
