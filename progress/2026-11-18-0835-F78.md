# F78: Claude Code is found through the login shell's `PATH`, and `jellymoon harness` says how

**What changed.** On branch `f78`, on `d0964ea`. ADR 0021, decision 1, as the row states it. When
`JELLYMOON_CLAUDE` is not set and `PATH` and the fixed places hold no harness, core asks the person's login shell
for its `PATH` and looks in those folders (`find.rs`, `find/shell.rs`, `find/shell/ask.rs`), on a Mac and on Linux.
`jellymoon harness` prints one line of JSON: found or not, how, and one fixed sentence with no folder in it
(`find/said.rs`). The smoke chain gains the step `harness`. `page.md` has the whole rule under "The login shell";
`install.md`, `run.md`, `smoke.md` and the ADR ("As built (F78)") are brought along. `app/` is not changed: no
call's shape changed, and the app already looks for the harness off the thread that draws.

`passes` stays false. The hand check the ADR asks for is not done: nobody has run this with `JELLYMOON_SHELL` and
`JELLYMOON_CLAUDE` not set on a Mac whose `claude` is under a version manager. Who did it and when goes here.

**How the login shell is known.** `JELLYMOON_SHELL` names it; set to nothing, none is asked. Not set, core starts
the system's own program for the record of the user by its full path with no variable: `/usr/bin/id -P` on a Mac,
`/usr/bin/getent passwd <uid>` elsewhere, 2 seconds and 4,096 bytes at most. No `unsafe`, no new package. A file of
the system was not taken, since a Mac keeps no person's account in `/etc/passwd`. No test runs this: only the
reading of a record typed by hand is tested.

**What was red.** `cargo test -p jellymoon --test f78` against the parent's sources: 11 of 11 failed. The look
ended with today's line and no login shell among the places, and `harness` was no command. Now 11 pass, and core
has 6 tests of its own under `find::`.

**The door.** A test cannot name a login shell that is not a full path: the door refuses it. That one rule of the
row's second step is held by a test in core (`find/shell/ask.rs`), which starts nothing. Every other rule is held
at the binary. A test's made-up login shell (`tests/support/fake_shell.rs`) passes the checks as a person's does:
under the name `zsh` or `bash`, mode 755, in a folder of the door's world. There is no seam for tests.

user. Every run of the mutations had `JELLYMOON_SHELL` set to nothing outside the door as well.

**Budgets.** Core 16357 to 16913, the binary 27679 to 28276, xtask 2767 to 2798. Nothing was deleted but the
sentence in `find.rs` and `page.md` that no shell is asked.

**Open.**
- The hand check above, and so the reading of the real record of the user. `id -P` and `getent` are not run by
  any test. Where `/usr/bin/getent` is not there, the look says the record named none.
- Linux and Windows were not run here. The Windows side is read, not compiled.
- The login shell gets a process group of its own, not a session. Started from a terminal, an interactive login
  shell can still open that terminal. From the Finder there is none.
- `fish` and every shell but `zsh` and `bash` are refused, in a sentence that says so.
- The slow case, a profile with a version manager in it, is not measured against the 5 seconds.
- F81 (a shim's started `PATH`) and F79 (the log) are not in this.
