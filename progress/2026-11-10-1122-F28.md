# F28 · the app draws a page from page data using only the kit (2026-11-10)

**What changed.** `crates/sticker-kit` and `app/` (`jellymoon-app`) were brought from the old F28 branch onto `main`
as files, not history: the shared files were changed by hand on top of main's. `cargo xtask check` now holds a crate
outside `crates/` to the rules. Two follow-ups from the restart's last review came first: every link in a word is a
link, and the reading's time test now fails without its limit (27 s against 10) and passes in 0.4 s with it.

**Evidence.** `make preflight` green on a Mac without Xcode's `metal`: 120 tests (core 28 + 3, binary 11 + 12, kit 32,
app 12 + 13, xtask 9). `cargo test -p jellymoon-app --test f28`: 13 passed, run with `--features runtime_shaders`, which
this Mac needs to build GPUI at all. Budgets are the measured counts: core 1691, binary 1106, xtask 411, kit 3982, app 1122.

**What's next.** The first CI run: Linux and Windows have never built GPUI here. Then the fresh-context review. F29
turns the taps the window logs into rulings.

**Surprising.** GPUI turns on `serde_json`'s `preserve_order` for the whole workspace build, so one F27 test that wrote
JSON with `json!` saw its keys in another order and its error column move; ADR 0013, point 6, has the rule that follows.
