# F17R: the per-PR check boots the server as a self-hoster runs it

**Changed.** F17 is re-scoped from a Workers preview to the pod-state server's own release form. `make e2e-deployed` builds the
bundle and runs `make deployed-boot`, which starts it as its own process and drives it by URL (refuses to start with no
database, test routes closed in the hosted shape, a pod through the real routes, the pod kept across `kill -9`). It then runs
the contract suite with the bundle as the server under test. CI's `e2e-preview` job is replaced by `e2e-deployed` (Postgres
service container, no secret). The `install` job is removed, since no install.sh exists and it only skipped. The `worker`
job now runs `make test-worker` (bun test fails when it finds no test), and `e2e-worker` errors instead of skipping when `e2e/`
is missing.

**Evidence.** Two green local runs of `make e2e-deployed` (STEPS 58/58); a wrong `DATABASE_URL` fails the job at boot. The
hosted shape needs a real Postgres, which this host does not have, so its branch runs for the first time in CI.

**Next.** Read the first CI log of `e2e-deployed` for the hosted-shape lines (401 without the bearer, 404 on the clock). At
land, the ruleset adds `e2e-deployed` and drops `install`. F17 stays `passes: false` until CI is green on the PR.

**Surprising.** The suite cannot take a URL: its tests kill and restart the server and need a fake clock that a hosted build
must not expose, so the hosted shape is checked by `deployed-boot` and the suite runs the same bundle in the local-test shape.
