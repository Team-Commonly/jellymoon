# A theme file names no pictures

One commit, branch `art-out`, off main at `7d67cd5`. A removal: custom art is taken out of theme files, by the
coordinator's ruling when PR 154 (the trial in a child) was closed without merging. The decision and the way back
are `docs/adr/0016-theme-files-name-no-pictures.md`; ADR 0015 is marked superseded.

## What changed

- `Theme::load` reads the theme file and no other. `Theme` has no `art` and no `folder`, so nothing holds a place
  to find a picture in. The `[art]` table of an older file is taken out before the unknown keys are named, with one
  warning: `art: pictures in a theme are not read in this version; the kit's own art is drawn`. It goes where
  warnings already go (the app prints the first 8, cleaned, as `jellymoon-app: theme: ` lines).
- `draw/sprites.rs` draws the kit's own art only; a new theme forgets the images of the last.
- Deleted: `theme/svg_check.rs`, `theme/svg_text.rs`, `tests/cost.rs`, `tests/limits.rs`, `tests/alike.rs`,
  `tests/art_draw.rs` (all of each was the door), and with them `ArtCost`, `art_cost`, `svg_refusal`,
  `Theme::art_svgs`, `Theme::folder`, `Art`, `ThemeError::RefusedSvg`, `MAX_ART_BYTES` and every other `MAX_ART_*`,
  `MIN_ART_*`, `ROW_PAINT` and `SVG_*` name; the heaviest-art test in `tests/draw.rs`.
- Dependencies: `usvg` and `svgtypes` leave the kit's `Cargo.toml` and the workspace's. `Cargo.lock` loses two
  lines, the two names under `sticker-kit`; the packages stay, since GPUI builds them for its own drawing.

Lines, against main and without this file: 158 added and 2162 removed. The kit's Rust is 70 added and 1989 removed (`src` 27 and 629,
tests 43 and 1360); the app's is 6 and 7; the kit README 13 and 143; docs 61 and 7 (52 are the new ADR). The
budgets are lowered to the count: the kit from 9001 to 7082, the app from 5519 to 5518.

## How F32's step is kept

The step: "a theme carries no code: a theme file containing a script or a path outside its folder is refused".
`feature_list.json` is not edited.

- A path outside the folder is still refused, `art.star = "../star.svg" leaves the theme's folder`. It was always
  a check of the key's text that opens nothing, and it is kept as that (`no_pictures` in `theme/load.rs`).
- A script could only be in a picture a theme names. That half of the test is now "such a file's pictures are
  never read": a theme beside three scripted pictures, beside none, and beside a folder of the picture's name
  loads as the same theme with the one warning (`tests/f32.rs` in the kit; `app/tests/f32.rs` at the binary, where
  `script.toml` used to exit 1 and now lays out the default page). The test keeps its name.

## Proof

- The two built-in themes look as before. The picture example was run on this branch and on main at `7d67cd5`
  (`cargo run -p sticker-kit --example snapshot`), and `kit-sticker.png` and `kit-plain.png` are the same bytes.
  `src/art.rs` and `theme/builtin.rs` are not in the diff. `tests/alike.rs` compared the door with the parser, not
  pictures, so it went with the door; the draw tests that stay (`tests/draw.rs`, `tests/entry_draw.rs`) pass.
- `make preflight`, `make smoke` and the Windows lint were green on a Mac. Not run on Linux or Windows.

## For a later reader

- Three tests in `tests/draw.rs` fail in a release test build (`cargo test -p sticker-kit --release --test draw`):
  `label_text_is_painted_where_the_layout_put_it`, `the_view_builds_for_both_themes` and
  `a_whole_option_written_smaller_is_painted_at_the_size_it_was_measured_at`. They fail on main's code too, and
  not from this change: each asks `debug_bounds` for a text run, and GPUI keeps a `debug_selector` only in a build
  with debug assertions. Not fixed here. `tests/entry_draw.rs` asks the same way.
- A theme file whose `art` is not a table (`art = 3`) gets the same warning. A name in the table that is not text
  is not looked at.
- The refusal of a path out of the folder is the only thing an `[art]` table can still do. If it reads as odd
  that a table which is not read can refuse a theme, it is there for F32's step and can go with a new feature.
- GLOSSARY's **pack** still says "data and art only": packs are the condition for art to return (ADR 0016).
- The design for art's return is PR 154, the branch `art-trial` and its own ADR 0016, which has this note's number.
